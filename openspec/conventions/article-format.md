# 文章内容格式规范

> 知识图谱的文章按什么结构写。所有 AI 写文章时遵循这个模板。

## 三种文章类型 + 统一骨架

| 类型 | 场景 | 长度 | 深度 |
|---|---|---|---|
| **概念科普**（concept） | 第一次学一个技术 | 3-5 分钟 | 浅（原理 + 示例） |
| **问题排查**（problem） | 遇到具体问题来查 | 5-15 分钟 | 中等（根因 + 方案 + 验证） |
| **实战深挖**（deep-dive） | 面试 / 复杂场景 / 架构选型 | 15-60 分钟 | 深（生产数字 + trade-off + 反思） |

**frontmatter 标记：**

```yaml
---
title: RocketMQ 事务消息在信贷场景的应用
type: deep-dive     # concept / problem / deep-dive
tags: [后端, 分布式事务, RocketMQ, 信贷]
---

```

## 统一骨架（每种类型都遵循）

```
# 标题（一句话点题）

> 一句话摘要：解决什么问题 / 学完能会什么 / 适用边界

## 1. 背景（Why 这个问题存在）
- 实际场景 / 不这么做会怎样
- 关键约束（性能、一致性、成本）

## 2. 核心内容（What & How）
- 原理 / 关键概念 / 最小可运行示例
- 关键参数 + 默认值

## 3. 实战 / 线上案例（deep-dive 必有，其他类型可省略）
- 我们系统怎么用的（带数据）
- 踩过的坑 + 怎么排查
- 线上配置（QPS / 线程数 / 超时）

## 4. Trade-off（为什么选 A 不选 B）
- 至少 2-3 个备选方案对比表
- 选择理由 + 代价

## 5. 反模式 / 常见误区
- ❌ 错误做法 + 后果
- ✅ 正确做法 + 为什么

## 6. 一句话总结
> 30 秒能讲完的核心

## 参考
- 官方文档
- 相关 ADR / 内部文档 / 推荐阅读
```

## 5W 原则速记卡（concept 类必备）

deep-dive 类不需要（已经在正文展开了）。**concept 类必须在文章末尾有 5W 表：**

| 维度 | 答案 |
|---|---|
| **What** | 一句话定义 |
| **Why** | 为什么需要 / 解决什么问题 |
| **When** | 何时用 / 何时不用 |
| **Where** | 适用场景 / 不适用场景 |
| **How** | 怎么做（链接正文详细步骤） |

**5W 是文章的「电梯版」**——读者扫一眼就能复述给别人。

## 类型专属规则

### concept（概念科普）

- ✅ **必须有 5W 表**
- ✅ 一个最小可运行代码示例
- ✅ 一张原理图或流程图（Mermaid 优先）
- ❌ 不要堆砌生产数字（不真实）
- ❌ 不要列 trade-off（读者还没学会不需要纠结选型）

### problem（问题排查）

- ✅ **标题用「问题描述」格式**（如「RocketMQ 消息积压如何排查」）
- ✅ 步骤清晰：**现象 → 原因 → 排查 → 解决 → 验证**
- ✅ 包含至少一个**真实报错信息 / 日志片段**
- ❌ 不要罗列所有可能原因（聚焦最常见的 2-3 个）

### deep-dive（实战深挖）

- ✅ **必须穿透八层**（是什么/为什么/怎么做/trade-off/坑/更好/生产画像/深度机制）
- ✅ 必须有生产数字（QPS/TPS/P99/线程数/连接池）
- ✅ 必须有 trade-off 章节
- ✅ 至少 2 个备选方案对比
- ✅ 结尾必须有**反思/回头看**（P7 杀手锏）
- ❌ 不要「忘了」「不清楚」（基础题没借口）

## 排版规则

### 标题层级

- `##` 一级章节（一个文章 3-7 个）
- `###` 二级章节
- `####` 三级章节（少用，超过 3 层考虑拆文章）

### 列表

- **要点列表**：用 `-` 不用 `1.`
- **步骤列表**：用 `1.` 标明顺序
- **避免**：超过 7 项的长列表（拆成多个段落或表格）

### 表格

- **对比/参数** → 表格
- **3 列以内** → 列表
- **表头要清晰**，**第一列** 总是「比较项」或「维度」

### 代码

- **必须可运行**：能 copy-paste 跑起来
- **加注释**：关键参数用 `// 为什么这么设` 说明
- **避免**：超过 50 行的代码块（链接到示例代码仓库）

### 引用

- **关键结论**：用 `>` blockquote
- **面试官原话 / 反问**：用 `> 你：「为什么不用 X」`
- **数据/数字**：用粗体 `**QPS 1200**` 不用引用块

## 篇幅指南

| 类型 | 字数 | 阅读时间 |
|---|---|---|
| concept | 800-2000 字 | 3-5 分钟 |
| problem | 2000-5000 字 | 5-15 分钟 |
| deep-dive | 5000-20000 字 | 15-60 分钟 |

**超过 2 万字 = 该拆成系列文章了**。

## frontmatter 完整示例

```yaml
---
title: RocketMQ 事务消息在信贷场景的应用
type: deep-dive
tags: [后端, 分布式事务, RocketMQ, 信贷, 满帮小贷]
date: 2025-07-25
test: true       # 占位文章，正式发布前去掉
wordCount: 4500  # 自动注入（scripts/inject-article-meta.cjs）
readMinutes: 12  # 自动注入
---
```

## AI 写文章 checklist

写作前：

- [ ] 确认类型（concept / problem / deep-dive）
- [ ] 选合适的目录（9 大类之一）
- [ ] 列出 3-5 个核心要点

写完后：

- [ ] 标题一句话点题
- [ ] 一句话摘要清晰
- [ ] 6 个标准章节都齐全
- [ ] 代码可运行 + 加注释
- [ ] 关键数字用粗体
- [ ] concept 类末尾有 5W 表
- [ ] deep-dive 类有 trade-off 表 + 反思
- [ ] 没有「忘了」「不清楚」（基础题没借口）
