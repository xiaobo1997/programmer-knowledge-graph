# Spring Boot 系列导读 · 从一个请求的一生认识 Spring Boot

> 📖 本系列共 24 篇（0_导读 + 1-23 正文），覆盖 Spring Boot 生态整个知识面：认知全景、IoC 容器、AOP 与事件、Web 层、数据访问、配置场景、测试生产 7 组。
> 本篇是第 0 篇导读：先建立全局心智模型，再决定读哪条路。
> Java 语言是独立系列（见 use-java），本系列默认读者已具备 Java 并发/JVM/反射基础。

## 一、为什么需要这套系列

Spring Boot 是 Java 后端的事实标准：公司里几乎每个服务都是 Boot 应用，简历上人人会写「熟悉 Spring Boot」。但绝大多数人只会「用」，不知道「为什么」：

- **只会背注解**：@Autowired 会加、@Transactional 会标，但循环依赖为什么能解、事务为什么失效、自动装配到底装了什么——一问就卡
- **遇错不会查**：启动报错看不懂、事务没生效不知道往哪看、线上问题只会重启

这套系列的设计思路：**先主线后支线**。主线是「一个请求的一生」——从 HTTP 请求打到 Controller，到事务提交、数据落库，把 Spring Boot 的核心机制串起来；支线是挂在这条主线上面的七组知识：IoC 容器（对象怎么管理）、AOP（横切逻辑怎么织入）、Web（请求怎么分发）、数据（事务怎么保证）、配置（环境怎么切换）、测试与生产（怎么保证质量与稳定）。主线通了，各组深挖时都知道「它在整条链路里处于什么位置」。

## 二、全局心智模型：一个请求的一生

```mermaid
flowchart LR
    subgraph CLIENT ["客户端"]
        direction LR
        HTTP[HTTP 请求<br/>JSON/表单]
    end
    subgraph WEB ["Web 层"]
        direction LR
        FILTER[Filter 过滤器]
        DISPATCHER[DispatcherServlet<br/>前端控制器]
        INTERCEPTOR[Interceptor 拦截器]
        HANDLER[HandlerMapping<br/>路由到 Controller]
        AOPW[AOP 切面<br/>日志/鉴权/事务代理]
        CONVERT[参数绑定与校验<br/>Jackson/Bean Validation]
        EXC[统一异常处理<br/>@RestControllerAdvice]
    end
    subgraph CORE ["IoC 容器核心"]
        direction LR
        BEAN[Bean 生命周期<br/>创建/注入/初始化]
        DI[依赖注入<br/>@Autowired]
        CONFIG[条件装配<br/>starter 自动配置]
    end
    subgraph DATA ["数据层"]
        direction LR
        TX[事务管理<br/>@Transactional]
        MAPPER[MyBatis Mapper<br/>SQL 执行]
        DS[数据源/连接池<br/>HikariCP]
        DB[(MySQL)]
        CACHE[(Redis 缓存)]
    end
    subgraph OPS ["配置与生产"]
        direction LR
        PROFILE[Profile 多环境]
        LOG[日志体系<br/>traceId]
        ACT[Actuator 监控]
    end
    HTTP --> FILTER --> DISPATCHER --> INTERCEPTOR --> HANDLER
    HANDLER --> AOPW --> CONVERT
    CONVERT --> BEAN
    BEAN -.业务调用.-> DI
    AOPW -.代理事务.-> TX
    TX --> MAPPER --> DS --> DB
    CONVERT -.缓存查询.-> CACHE
    CONVERT -.异常.-> EXC
    BEAN --> CONFIG
    CONFIG --> PROFILE
    MAPPER -.记录.-> LOG
    DISPATCHER -.暴露.-> ACT
```

一个请求的一生：

1. **过滤器 → 分发器**：HTTP 请求先过 Filter（跨域/编码），到达 DispatcherServlet 前端控制器——整个 Web MVC 的入口
2. **路由到 Handler**：HandlerMapping 根据 URL 找到对应的 Controller 方法，拦截器（Interceptor）在前后做横切
3. **AOP 代理**：目标方法可能被 AOP 切面包裹（日志/鉴权），@Transactional 的代理在这里生效——代理对象决定事务是否开启
4. **参数绑定与校验**：JSON 反序列化成对象（Jackson），Bean Validation 校验参数合法性
5. **业务执行**：Controller → Service 里的 Bean 从 IoC 容器来，依赖注入（@Autowired）在 Bean 创建时就接好了；Bean 的生命周期由容器管理
6. **数据访问**：Service 调 Mapper → 连接池（HikariCP）拿连接 → MySQL 执行 SQL；事务保证多步写操作的原子性
7. **返回与异常**：正常返回经响应封装，异常抛给 @RestControllerAdvice 统一处理成错误码响应
8. **生产环境**：Profile 切换环境配置，日志带 traceId 串联链路，Actuator 暴露健康检查给监控

> tips：(知识地图) 这条主线是整套 Spring Boot 知识的主干：7 组知识全部挂在「一个请求的一生」上——IoC 管对象从哪来、AOP 管横切怎么织、Web 管请求怎么分发、事务管数据怎么一致、配置管环境怎么切，先主线后支线，比孤立背注解快得多。

## 四、阅读路径

- **新手 / 系统补一遍**：按 1-23 顺序通读入门层（7 组顺读，每篇 20-40 分钟）
- **工作/面试优先**：组 B IoC（3-6）+ 组 E 数据（13-16）权重最高——循环依赖、事务失效是高频考点
- **写接口日常**：组 D Web（9-12）当手册翻（参数校验/异常封装直接抄规范）
- **进阶深入**：对哪篇有疑问，沿该篇进特性层源码走读（自动装配/IoC/AOP/Web MVC），再到专题层组合实战
- **业务落地**：组 E 数据访问（13-16）+ 组 G 测试生产（20-23）直接对业务开发；整合层主题待定，等真实业务实践落位

## 六、一句话总结

> Spring Boot 的知识地图只有一张：**一个请求的一生**——过过滤器进 DispatcherServlet，经 AOP 代理到 Controller，Bean 从 IoC 来、事务保证一致、连接池落库，异常统一收口。主线通了，23 篇全是支线深挖的入口。
