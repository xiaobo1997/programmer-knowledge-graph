# 事务管理

> @Transactional 的原理与传播行为七种、隔离级别、以及必知的失效场景大全——事务是数据一致性的第一道防线。

> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 规划大纲

### 1. 背景：事务为什么重要

- ACID 与金融数据一致性
- 声明式事务 vs 编程式事务

### 2. 核心：@Transactional 使用

- 注解属性全景（rollbackFor/readOnly/timeout）
- 默认只回滚 RuntimeException 的陷阱
- 自调用与代理失效

### 3. 机制：传播行为与隔离级别

- 七种传播行为（REQUIRED/REQUIRES_NEW/NESTED…）
- 隔离级别与数据库对应
- 读已提交 vs 可重复读的工程选择

### 4. 实践：失效场景排查手册

- 非 public 方法/同类调用/异常被吞等经典失效
- 事务边界设计（大事务拆分）
- 与多数据源事务的边界（16 篇衔接）
