# MyBatis-Plus 系列导读 · 一个 Mapper 方法的一生

> 📖 本系列共 17 篇（0_导读 + 1-16 正文），覆盖 MyBatis-Plus 生态整个知识面：认知集成、CRUD 核心、特色功能、高级机制、生态生产 5 组。
> 本篇是第 0 篇导读：先建立全局心智模型，再决定读哪条路。
> 本系列是 Spring Boot 系列的兄弟系列——Spring Boot 15 讲原生 MyBatis 接入，MyBatis-Plus 的增强全家桶（BaseMapper / 条件构造器 / 插件 / SQL 注入器）在这里讲透。

## 一、为什么需要这套系列

国内 Java 后端开发，MyBatis-Plus 几乎是「开箱即用」的标配：一个 `BaseMapper` 接口继承下去，单表 CRUD 不用写一行 SQL；条件构造器拼 where 条件；分页插件一装，`Page` 对象直接返回。但用得越顺手，越容易只停留在「API 调用层」：

- **只会继承 BaseMapper**：知道 `selectById` 能查，不知道这条 SQL 是**什么时候、被谁、怎么拼出来**的——启动时注入器生成 MappedStatement？还是运行时反射？
- **只会 new QueryWrapper**：知道能拼条件，不知道 Lambda 版为什么能防 SQL 注入、`ew.customSqlSegment` 怎么和 XML 协作
- **只会装分页插件**：知道 page 能翻页，不知道物理分页是怎么拦截改写 SQL 的、为什么深翻页会慢

这套系列的设计思路：**主线 = 一个 Mapper 方法的一生**。从你调用 `userMapper.selectPage(page, wrapper)` 开始，到这条 SQL 真正落库返回，中间经过：实体与表的映射（TableInfo）→ 方法对应的 SQL 模板（注入器生成）→ 条件构造器拼 where → 插件拦截器链（分页改写/乐观锁版本号/多租户过滤）→ MyBatis 执行器 → 数据库。主线通了，5 组知识全挂在上面，每一篇都知道「它在整条链路里处于什么位置」。

## 二、全局心智模型：一个 Mapper 方法的一生

```mermaid
flowchart LR
    subgraph CALL ["调用侧"]
        direction LR
        CALLER[业务代码<br/>userMapper.selectPage]
        WRAPPER[条件构造器<br/>LambdaQueryWrapper]
    end
    subgraph START ["启动期准备"]
        direction LR
        ENTITY[实体类<br/>@TableName/@TableId]
        TABLEINFO[TableInfo<br/>表-字段映射]
        INJECTOR[SQL 注入器<br/>ISqlInjector]
        METHOD[AbstractMethod<br/>拼 SQL 模板]
    end
    subgraph RUN ["运行时链路"]
        direction LR
        INTERCEPTOR[插件拦截器链<br/>MybatisPlusInterceptor]
        PAGE[分页插件<br/>改写 SQL 加 LIMIT]
        OPT[乐观锁插件<br/>版本号 +1]
        TENANT[多租户插件<br/>自动拼 tenant_id]
        EXEC[MyBatis 执行器<br/>Executor]
        DB[(MySQL)]
    end
    CALLER --> WRAPPER
    CALLER --> ENTITY
    ENTITY --> TABLEINFO
    TABLEINFO --> METHOD
    INJECTOR --> METHOD
    METHOD --> CALLER
    WRAPPER --> INTERCEPTOR
    CALLER --> INTERCEPTOR
    INTERCEPTOR --> PAGE
    INTERCEPTOR --> OPT
    INTERCEPTOR --> TENANT
    PAGE --> EXEC
    EXEC --> DB
```

一个 Mapper 方法的一生：

1. **启动期**：Spring Boot 扫描到你的 `UserMapper extends BaseMapper<User>`，MP 的注册器把它接住
2. **TableInfo 建立**：解析 `User` 实体上的 `@TableName("t_user")`、`@TableId`、`@TableField`，建立实体 ↔ 表的映射元数据
3. **SQL 注入**：SQL 注入器（ISqlInjector）遍历 BaseMapper 里每个方法（selectById/insert/updateById…），每个方法配一个 AbstractMethod 实现——它负责把方法名、TableInfo、参数拼成一条 SQL 模板，注册成 MyBatis 的 MappedStatement（启动时就绪，运行时不再拼）
4. **调用**：业务代码调 `selectPage(page, wrapper)`，条件构造器把 Java 条件（eq/ge/like…）解析成 where 片段 + 参数
5. **插件链**：请求穿过 MybatisPlusInterceptor 的 InnerInterceptor 链——分页插件在这里拦截 SQL、按方言改写（MySQL 加 LIMIT）并执行 COUNT 查询；乐观锁插件给 updateById 自动拼 version 条件并把版本号 +1；多租户插件自动拼 tenant_id 条件
6. **执行**：真正交给 MyBatis 的 Executor 落库/查询，返回 Page 对象（records + total）或实体

> tips：(知识地图) 整套 MP 只有一条主线：启动期「实体 → TableInfo → 注入器 → SQL 模板」定好每个方法长什么样，运行时「条件构造器拼 where → 插件链改写 → 执行器落库」走一遍。分页/乐观锁/逻辑删除/多租户全是插件链上的 InnerInterceptor——理解插件机制（14 篇）就理解了 MP 一半。

## 四、阅读路径

- **新手 / 系统补一遍**：按 1-16 顺序通读入门层（5 组顺读，每篇 20-30 分钟）
- **工作/面试优先**：组 B（3-6）+ 组 E 的 14——BaseMapper 怎么注入、Wrapper 怎么防注入、插件怎么拦截是高频考点
- **日常 CRUD 开发**：组 B + C（3-10）当手册翻（条件构造器/分页/逻辑删除直接抄规范）
- **进阶深入**：对哪篇有疑问，沿该篇进特性层源码走读（条件构造器/插件机制/SQL 注入器），再到专题层组合实战
