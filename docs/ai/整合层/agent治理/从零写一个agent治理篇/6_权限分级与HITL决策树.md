# §6 权限分级 + HITL 决策树：风控 + 客服

## 一句话摘要

权限分级 + HITL 决策树 的核心要点与实践指导。

**5W 速记卡**：
- **What**：L0-L3 权限分级 + HITL 决策树
- **Why**：风控和客服都需要权限控制
- **Who**：做了风控/客服 agent 的工程师
- **When**：设计权限体系时
- **Where**：风控 agent + 客服 agent

**自测三问**：
1. 本文核心机制：L0-L3 + HITL 矩阵
2. 失效点：权限过宽 → 安全事故
3. 与下篇衔接：权限分级 → 审计日志

---

## 6.1 思考：权限分级为什么重要

**核心问题**：agent 权限为什么需要分级？

答案：agent 能调工具 = 能调 API = 能改数据 = 能删记录。不做权限分级，agent 可以做任何事——包括删数据库、改规则、冻结账户。

**权限分级的核心思想**：
- L0 只读（查数据）
- L1 写业务数据（标记/创建）
- L2 外部副作用（拦截/退款）
- L3 系统级（删除/改配置）

**核心口诀**：**agent 默认 L0，L1+ 必须显式授权，任何授权可立即撤销。**

## 6.2 风控 agent L0-L3 映射

| 级别 | 风控场景 | 风险 | 授权方式 |
|---|---|---|---|
| **L0 只读** | 查交易 / 查规则 / 查黑名单 | 低 | 默认允许 |
| **L1 写业务数据** | 标记风险 / 记录日志 | 中 | 显式授权 |
| **L2 外部副作用** | 拦截交易 / 冻结账户 | 高 | 强制 HITL |
| **L3 系统级** | 删交易 / 改规则 / shell | 极高 | 强制 HITL + 多重审计 |

## 6.3 客服 agent L0-L3 映射

| 级别 | 客服场景 | 风险 | 授权方式 |
|---|---|---|---|
| **L0 只读** | 查订单 / 查费率 / 查结算 | 低 | 默认允许 |
| **L1 写业务数据** | 创建工单 / 标记用户 | 中 | 显式授权 |
| **L2 外部副作用** | 退款 / 转账 / 发通知 | 高 | 强制 HITL |
| **L3 系统级** | 删订单 / 改规则 / shell | 极高 | 强制 HITL + 多重审计 |

## 6.4 HITL 决策树（风控 + 客服）

**HITL 矩阵**：

| 风险等级 | HITL 必要性 | 风控审批人 | 客服审批人 | 决策权 |
|---|---|---|---|---|
| L0 只读 | ❌ 不需要 | - | - | agent 自动 |
| L1 业务 | ⚠️ 抽样（10%）| 业务 owner | 业务 owner | agent 自动 + 事后审计 |
| L2 外部 | ✅ 必审批（实时）| 业务 owner | 业务 owner | 人工实时审批 |
| L3 系统 | ✅✅ 双人审批（实时）| 业务 + 技术 owner | 业务 + 技术 owner | 人工双人审批 |

## 6.5 权限分级的 5 个设计原则

1. **最小权限**——agent 默认只能做 L0
2. **显式授权**——L1+ 必须显式授权
3. **可撤销**——任何授权可立即撤销
4. **审计留痕**——每个权限检查留审计日志
5. **定期审查**——定期审查权限分配

## 6.6 降级方法（4 种）

| 降级方法 | 适用场景 | 示例 |
|---|---|---|
| 批量审批 | L1 抽样 | 10% 抽样批量审批 |
| 异步审批 | L2/L3 | 人工审批队列 |
| 自动审批 + 事后审计 | L1 | 自动审批 + 事后审计 |
| 智能审批 | L1/L2 | AI 辅助决策 |

## 6.7 风控 vs 客服权限对比

| 维度 | 风控 agent | 客服 agent |
|---|---|---|
| L0 | 查交易 / 查规则 | 查订单 / 查费率 |
| L1 | 标记风险 / 记录日志 | 创建工单 / 标记用户 |
| L2 | 拦截交易 / 冻结账户 | 退款 / 转账 |
| L3 | 删交易 / 改规则 | 删订单 / 改规则 |
| HITL 核心 | 拦截/冻结必须审批 | 退款/删除必须审批 |
| PII 风险 | 卡号/身份证 | 姓名/地址/电话 |
