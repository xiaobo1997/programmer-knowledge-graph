# §2 数据安全治理：敏感数据上传

## 一句话摘要

数据安全治理 的核心要点与实践指导。

**5W 速记卡**：
- **What**：数据安全 = 数据分类 + 脱敏 + 权限 + 审计
- **Why**：AI 工具上传数据 → 泄露风险
- **Who**：开发者 + 数据安全团队
- **When**：使用 AI 工具时
- **Where**：企业内网

**自测三问**：
1. 本文核心机制：数据分类 → 脱敏 → 权限 → 审计
2. 失效点：数据泄露 → 合规风险
3. 与下篇衔接：数据安全 → 代码安全

---

## 2.1 思考：AI 工具上传数据的风险

**核心问题**：用 AI 工具时，数据怎么泄露？

风险场景：
1. 代码上传（GitHub Copilot / Cursor）
2. 文档上传（ChatGPT / Claude）
3. 数据上传（AI 分析工具）
4. 日志上传（AI 监控工具）

## 2.3 数据分类

**数据分类是什么？**——按敏感程度分类。

分类标准：
- 公开数据（可公开）
- 内部数据（内部使用）
- 敏感数据（需脱敏）
- 机密数据（严格限制）

## 2.4 脱敏处理

**脱敏处理是什么？**——敏感数据脱敏后再上传。

脱敏方法：
- 匿名化（移除标识）
- 伪名化（替换标识）
- 加密（加密传输）
- 哈希（不可逆）

## 2.5 权限控制

**权限控制是什么？**——控制谁可以上传什么数据。

权限策略：
- 最小权限（只给必要权限）
- 角色权限（按角色分配）
- 审批权限（敏感数据需审批）

## 2.6 审计记录

**审计记录是什么？**——记录数据上传的审计日志。

审计内容：
- 上传了什么数据
- 谁上传的
- 什么时候上传的
- 上传到哪里

## 2.7 治理实践

| 实践 | 做什么 | 优先级 |
|---|---|---|
| 数据分类 | 按敏感程度分类 | P0 |
| 脱敏处理 | 敏感数据脱敏 | P0 |
| 权限控制 | 控制上传权限 | P0 |
| 审计记录 | 记录审计日志 | P1 |
| 定期审查 | 定期审查策略 | P1 |

## 2.8 AI 工具场景

| AI 工具 | 风险 | 治理措施 |
|---|---|---|
| GitHub Copilot | 代码上传 | 代码脱敏 + 权限控制 |
| Cursor | 代码上传 | 代码脱敏 + 权限控制 |
| ChatGPT | 文档上传 | 文档脱敏 + 审批 |
| Claude | 文档上传 | 文档脱敏 + 审批 |

## 2.9 常见反模式

| 反模式 | 表现 | 代价 | 正确做法 |
|---|---|---|---|
| 无数据分类 | 全部上传 | 泄露风险 | 数据分类 |
| 无脱敏 | 敏感数据明文 | 泄露风险 | 脱敏处理 |
| 无权限控制 | 任何人可上传 | 泄露风险 | 权限控制 |
| 无审计记录 | 上传不记录 | 无法追溯 | 审计记录 |

## 2.10 治理要点

**治理要点**：
- 数据分类是基础
- 脱敏是核心
- 权限是保障
- 审计是追溯
