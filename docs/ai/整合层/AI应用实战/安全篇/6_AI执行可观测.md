# §6 AI 执行可观测：Trace + 日志 + 指标 + 告警

## 一句话摘要

AI 执行可观测 的核心要点与实践指导。

**5W 速记卡**：
- **What**：AI 执行可观测 = Trace + 日志 + 指标 + 告警
- **Why**：AI 执行需要可观测才能发现问题
- **Who**：运维 + 开发者
- **When**：AI 执行时
- **Where**：业务系统

**自测三问**：
1. 本文核心机制：AI 执行 → Trace + 日志 + 指标 → 告警
2. 失效点：AI 执行不可观测 → 问题发现慢
3. 与下篇衔接：AI 执行可观测 → 发现问题方法论

## 6.3 Trace

**Trace 是什么？**——追踪 AI 执行的全链路。

Trace 包含：
- 请求链路
- 执行路径
- 耗时
- 状态

## 6.4 日志

**日志是什么？**——记录 AI 执行的日志。

日志包含：
- 输入日志
- 输出日志
- 错误日志
- 调试日志

## 6.5 指标

**指标是什么？**——AI 执行的度量指标。

指标包含：
- 准确率
- 响应时间
- 吞吐量
- 错误率

## 6.6 告警

**告警是什么？**——AI 执行异常时告警。

告警包含：
- 错误告警
- 性能告警
- 容量告警
- 业务告警

## 6.7 可观测实践

| 实践 | 做什么 | 优先级 |
|---|---|---|
| Trace | 追踪全链路 | P0 |
| 日志 | 记录执行日志 | P0 |
| 指标 | 监控指标 | P0 |
| 告警 | 异常告警 | P0 |
| 仪表盘 | 可视化 | P1 |

## 6.8 与传统监控的对比

| 维度 | 传统监控 | AI 执行可观测 |
|---|---|---|
| 监控对象 | 服务 | AI 执行 |
| 指标 | CPU/内存 | 准确率/响应时间 |
| 告警 | 阈值 | 异常检测 |
| 根因 | 日志分析 | Trace + 日志 |

## 6.9 常见反模式

| 反模式 | 表现 | 代价 | 正确做法 |
|---|---|---|---|
| 无 Trace | 链路不清晰 | 无法定位 | Trace |
| 无日志 | 问题难定位 | 排查慢 | 日志 |
| 无指标 | 无法度量 | 无法优化 | 指标 |
| 无告警 | 异常不发现 | 问题积累 | 告警 |

## 6.10 治理要点

**治理要点**：
- Trace + 日志 + 指标 + 告警
- 全链路可观测
- 异常检测
