# §5 文档先行：如何保证文档与代码同步

## 一句话摘要

文档先行 的核心要点与实践指导。

**5W 速记卡**：
- **What**：文档先行 = 代码变更 → 文档同步 + 文档审查 + 自动化检查
- **Why**：文档与代码同步是 SDD 的核心治理机制
- **Who**：每个开发者 + 团队leader
- **When**：代码变更时
- **Where**：团队 + 个人

**自测三问**：
1. 本文核心机制：代码变更 → 文档同步 → 文档审查 → 自动化检查
2. 失效点：文档滞后 → 技术债
3. 与下篇衔接：文档先行 → 持续产出体系

---

## 5.1 思考：文档与代码不同步的根因

**核心问题**：为什么文档总是滞后于代码？

根因分析：
1. **无约束**：代码变更不需要同步文档
2. **无审查**：文档质量没人检查
3. **无自动化**：文档更新靠人工，容易遗漏
4. **无激励**：写文档没有即时收益

## 5.2 文档先行机制

**文档先行机制是什么？**——代码变更必须同步文档。

文档先行机制包含：
- 代码变更 → 文档同步（自动触发）
- 文档审查（质量检查）
- 自动化检查（CI 集成）

## 5.4 代码变更 → 文档同步

**代码变更 → 文档同步是什么？**——代码变更自动触发文档更新。

同步方式：
- 代码注释 → API 文档（自动生成）
- 代码结构 → 设计文档（手动更新）
- 代码变更 → 变更日志（自动记录）

## 5.5 文档审查

**文档审查是什么？**——检查文档质量。

审查内容：
- 文档是否完整
- 文档是否准确
- 文档是否及时

## 5.6 自动化检查

**自动化检查是什么？**——CI 集成文档检查。

检查项：
- 文档是否存在
- 文档是否最新
- 文档格式是否正确

## 5.7 SDD 中文档先行的实践

| 实践 | 做什么 | 优先级 |
|---|---|---|
| 文档即契约 | 代码必须符合文档 | P0 |
| 代码变更 → 文档同步 | 自动触发 | P0 |
| 文档审查 | 质量检查 | P1 |
| 自动化检查 | CI 集成 | P1 |
| 文档即代码 | 文档在仓库 | P0 |

## 5.8 AI 辅助下的文档先行

**AI 辅助下的文档先行是什么？**——AI 帮你写文档 + 保持同步。

AI 辅助做什么：
- 代码生成文档（代码 → 文档）
- 文档审查（检查质量）
- 文档同步（代码变更 → 文档更新）

**核心原则**：AI 辅助文档先行——AI 生成文档 + 人工审查。

## 5.9 常见反模式

| 反模式 | 表现 | 代价 | 正确做法 |
|---|---|---|---|
| 无文档先行 | 代码没有文档 | 技术债 | 文档先行 |
| 文档不同步 | 文档过时 | 误导 | 代码变更 → 文档同步 |
| 无审查 | 文档质量差 | 误导 | 文档审查 |
| 无自动化 | 人工更新遗漏 | 不一致 | CI 集成 |

## 5.10 治理要点

**治理要点是什么？**——文档先行的治理机制。

治理要点：
- 文档即契约（代码必须符合文档）
- 代码变更 → 文档同步（自动触发）
- 文档审查（质量检查）
- 自动化检查（CI 集成）
