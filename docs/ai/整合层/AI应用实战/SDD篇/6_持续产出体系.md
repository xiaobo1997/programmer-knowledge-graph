# §6 持续产出体系：团队 + 个人持续迭代

## 一句话摘要

持续产出体系 的核心要点与实践指导。

**5W 速记卡**：
- **What**：持续产出 = 迭代 + 复盘 + 知识库更新
- **Why**：持续产出，避免知识断层
- **Who**：团队 + 个人
- **When**：日常开发
- **Where**：团队 + 个人

**自测三问**：
1. 本文核心机制：迭代 → 复盘 → 知识库更新 → 持续产出
2. 失效点：知识断层 → 团队效率下降
3. 与下篇衔接：持续产出 → 总结

---

## 6.1 思考：为什么需要持续产出

**核心问题**：团队 + 个人怎么持续产出？

答案：持续产出 = 小步快跑 + 复盘总结 + 知识库更新。AI 辅助加速开发，但持续产出需要体系支撑——不是一次性冲刺，是持续迭代。

## 6.3 迭代（小步快跑）

**迭代是什么？**——小步快跑，持续交付。

迭代包含：
- 小步交付（每次小功能）
- 快速验证（验证效果）
- 持续改进（改进流程）

## 6.4 复盘（总结 + 反思）

**复盘是什么？**——项目结束后的总结 + 反思。

复盘包含：
- 项目目标（做了什么）
- 实现过程（怎么做）
- 成果（交付了什么）
- 反思（哪里做得好/不好）
- 改进（下次怎么做更好）

## 6.5 知识库更新

**知识库更新是什么？**——持续沉淀新知识。

知识库更新包含：
- 业务知识更新（新规则 + 新模型）
- 技术知识更新（新架构 + 新设计）
- 经验知识更新（新踩坑 + 新最佳实践）

## 6.6 团队共享

**团队共享是什么？**——团队协作 + 同步。

团队共享包含：
- 知识库共享（团队可见）
- 决策共享（团队共识）
- 经验共享（团队学习）

## 6.7 持续产出实践

| 实践 | 做什么 | 优先级 |
|---|---|---|
| 迭代 | 小步快跑 | P0 |
| 复盘 | 总结 + 反思 | P0 |
| 知识库更新 | 沉淀新知识 | P0 |
| 团队共享 | 协作 + 同步 | P1 |
| 持续改进 | 改进流程 | P1 |

## 6.8 AI 辅助下的持续产出

**AI 辅助下的持续产出是什么？**——AI 加速迭代 + 复盘的效率。

AI 辅助做什么：
- 代码生成（加速迭代）
- 文档生成（加速复盘）
- 知识库更新（自动沉淀）
- 代码审查（加速验证）

**核心原则**：AI 辅助持续产出——AI 加速 + 人工决策。

## 6.9 常见反模式

| 反模式 | 表现 | 代价 | 正确做法 |
|---|---|---|---|
| 无迭代 | 一次性交付 | 技术债 | 小步快跑 |
| 无复盘 | 经验流失 | 重复犯错 | 定期复盘 |
| 无知识库更新 | 知识断层 | 无人使用 | 持续更新 |
| 无团队共享 | 信息孤岛 | 重复造轮子 | 团队共享 |

## 6.10 治理要点

**治理要点是什么**——持续产出的治理机制。

治理要点：
- 迭代机制（小步快跑）
- 复盘机制（总结 + 反思）
- 知识库更新机制（持续沉淀）
- 团队共享机制（协作 + 同步）
