# §1 为什么写：SDD + AI 辅助开发的治理命题

## 一句话摘要

为什么写 的核心要点与实践指导。

**5W 速记卡**：
- **What**：SDD（Spec-Driven Development）+ AI 辅助开发的治理
- **Why**：AI 加速开发但文档滞后 → 技术债 + 知识断层
- **Who**：用 AI 做开发的工程师 + 团队leader
- **When**：2026 年，AI 辅助开发已成主流
- **Where**：团队 + 个人

**自测三问**：
1. 本文核心机制：SDD = 文档先行 + AI 辅助 + 知识库 + 持续产出
2. 失效点：文档滞后 → 技术债
3. 与下篇衔接：为什么写 → SDD 全景

---

## 1.1 思考：AI 辅助开发的隐形成本

AI 辅助开发（Copilot / Claude Code / Codex / Cursor）让编码加速 2-5 倍，但带来隐形成本：

1. **文档滞后**：代码快了，文档没跟上
2. **知识断层**：团队共享 AI 生成代码，没人知道为什么
3. **技术债累积**：AI 生成 ≠ 优质代码
4. **知识库腐化**：个人知识库没人维护

**核心矛盾**：AI 加速开发，但加速的不是文档，是代码。文档跟不上 → 技术债 → 知识断层 → 团队效率下降。

## 1.2 SDD 是什么

SDD（Spec-Driven Development）= 文档先行驱动开发。

SDD 核心：
- 先写文档（需求 + 设计 + 接口）
- 再写代码（AI 辅助生成）
- 文档即契约（代码必须符合文档）
- 文档持续更新（代码变更 → 文档同步）

SDD 不是新概念，但 AI 让它变得可行——AI 可以帮你写文档 + 写代码 + 保持同步。

## 1.3 与传统开发的对比

| 维度 | 传统开发 | SDD + AI |
|---|---|---|
| 文档 | 代码后补（经常滞后） | 文档先行（代码同步） |
| 编码 | 手动 | AI 辅助 |
| 知识库 | 没人维护 | 持续沉淀 |
| 技术债 | 累积 | 可控（文档即契约） |
| 团队协作 | 靠沟通 | 靠文档 |

## 1.8 Trade-off 概览

- 文档先行 vs 快速迭代：文档越详细，迭代越慢
- 知识库共享 vs 个人隐私：团队共享 vs 个人沉淀
- AI 辅助 vs 人工审核：AI 越快，越需要人工审核
- 持续产出 vs 短期产出：长期积累 vs 短期交付
