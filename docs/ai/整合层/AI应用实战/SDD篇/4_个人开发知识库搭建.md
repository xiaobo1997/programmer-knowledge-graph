# §4 个人开发知识库搭建：个人沉淀

## 一句话摘要

个人开发知识库搭建 的核心要点与实践指导。

**5W 速记卡**：
- **What**：个人知识库 = 个人经验 + 技术笔记 + 项目复盘
- **Why**：个人沉淀，避免重复造轮子
- **Who**：每个开发者
- **When**：日常开发 + 项目结束
- **Where**：个人

**自测三问**：
1. 本文核心机制：个人知识库 = 经验 + 笔记 + 复盘
2. 失效点：知识库腐化 → 无人维护
3. 与下篇衔接：个人知识库 → 团队持续产出

---

## 4.1 思考：为什么需要个人知识库

**核心问题**：个人开发者怎么沉淀 AI 辅助开发的经验？

答案：AI 辅助开发让编码加速，但个人经验容易流失——换个项目、换家公司，之前的经验就没了。个人知识库 = 把经验沉淀下来，持续积累。

## 4.3 技术笔记

**技术笔记是什么？**——记录技术问题的解决过程。

技术笔记包含：
- 问题描述（遇到什么问题）
- 解决过程（怎么解决的）
- 解决方案（最终方案）
- 反思（下次怎么做更好）

## 4.4 项目复盘

**项目复盘是什么？**——项目结束后的总结。

项目复盘包含：
- 项目目标（做了什么）
- 实现过程（怎么做）
- 成果（交付了什么）
- 反思（哪里做得好/不好）

## 4.5 工具链

**工具链是什么？**——开发者日常使用的工具。

工具链包含：
- 编辑器（VS Code / Cursor）
- AI 工具（Copilot / Claude Code / Codex）
- 知识库工具（Obsidian / Notion）
- 部署工具（Docker / K8s）

## 4.6 最佳实践

**最佳实践是什么？**——已验证的、可复用的方法。

最佳实践包含：
- 已验证的编码习惯
- 已验证的 AI 使用方法
- 已验证的知识库维护方法

## 4.7 搭建步骤

| 步骤 | 做什么 | 产出 | 优先级 |
|---|---|---|---|
| ① 选择工具 | 选一个知识库工具 | 工具配置 | P0 |
| ② 记录技术笔记 | 踩坑 + 解决 | 技术笔记 | P0 |
| ③ 项目复盘 | 项目结束总结 | 复盘文档 | P1 |
| ④ 沉淀最佳实践 | 已验证的方法 | 最佳实践 | P1 |
| ⑤ 定期回顾 | 每周/每月回顾 | 回顾记录 | P0 |

## 4.8 与 AI 辅助的关系

| AI 辅助环节 | 个人知识库作用 |
|---|---|
| 代码生成 | 记录 AI 生成代码的验证结果 |
| 代码审查 | 记录 AI 审查的建议 |
| 重构建议 | 记录 AI 重构的效果 |
| 文档生成 | 记录 AI 生成文档的质量 |

**核心原则**：AI 辅助需要个人知识库沉淀——没有沉淀，AI 生成 = 一次性消费。

## 4.9 维护机制

**维护机制是什么？**——个人知识库持续更新的机制。

维护机制包含：
- 记录时机（遇到问题 → 记录）
- 回顾频率（每周/每月）
- 整理方法（分类 + 标签）

## 4.10 常见反模式

| 反模式 | 表现 | 代价 | 正确做法 |
|---|---|---|---|
| 从不记录 | 经验流失 | 重复造轮子 | 遇到问题就记录 |
| 记录不整理 | 知识混乱 | 找不到 | 分类 + 标签 |
| 从不回顾 | 知识过时 | 不够用 | 定期回顾 |
| 过于详细 | 信息过载 | 无人阅读 | 精简 + 索引 |
