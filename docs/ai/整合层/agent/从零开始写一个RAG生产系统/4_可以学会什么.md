## 4.1 能力 1：文档分块

**能做什么**：把任意文档（PDF/TXT/Markdown）按语义切分成 chunk

**理解什么**：
- 为什么 chunk 太小 → 上下文不连贯
- 为什么 chunk 太大 → 检索不精确
- 递归分块 vs 固定大小分块：各自适用场景

**可验证标准**：
```bash
python chunker.py --file docs/费率表.md --chunk-size 512 --overlap 50
# 输出：chunk_001.json ~ chunk_050.json，每个 chunk 有 id + content + metadata
```

## 4.2 能力 2：向量化

**能做什么**：将文本 chunk 转换为向量 embedding

**理解什么**：
- 为什么用 embedding：文本 → 数值向量 → 语义距离可计算
- 为什么用余弦相似度：衡量两个向量的语义相似程度
- OpenAI Embeddings vs BGE 模型：精度/成本/隐私对比

**可验证标准**：
```bash
python embedding.py --input chunks/ --output vectors/
# 输出：每个 chunk 有 embedding 向量，维度 1536（OpenAI）
```

## 4.3 能力 3：向量存储

**能做什么**：将 embedding 持久化到向量数据库

**理解什么**：
- 为什么用向量库：海量向量快速相似检索
- ChromaDB vs Milvus vs Qdrant：单机 vs 分布式
- 索引类型（IVF/HNSW）对检索速度的影响

**可验证标准**：
```bash
python vector_store.py --vectors vectors/ --store chromadb
# 输出：chroma/ 目录，persistable 向量存储
```

## 4.4 能力 4：检索

**能做什么**：根据用户查询，从向量库中检索相关 chunk

**理解什么**：
- 为什么向量检索：语义相似 ≠ 关键词匹配
- 为什么混合检索：向量（语义）+ 关键词（精确）互补
- Top-K 选择：K 太小漏relevant，K 太大噪声多

**可验证标准**：
```bash
python retriever.py --query "结算周期是 T+1 还是 T+2" --top-k 5
# 输出：5 个相关 chunk，带相似度分数
```

## 4.5 能力 5：重排

**能做什么**：对检索结果精排，提升精度

**理解什么**：
- 为什么需要重排：检索是粗排，重排是精排
- Cross-encoder vs Cross-encoder：精度 vs 延迟 trade-off
- 重排阈值：低于阈值的不召回

**可验证标准**：
```bash
python reranker.py --query "结算周期" --chunks chunk_001.json chunk_002.json
# 输出：重排后的 chunk 列表，按相关性排序
```

## 4.6 能力 6：上下文组装

**能做什么**：将检索结果 + 用户查询拼成 LLM prompt

**理解什么**：
- 为什么上下文组装：LLM 需要上下文才能基于知识回答
- 上下文窗口限制：太多 token → 截断/成本；太少 → 信息不足
- Prompt 模板设计：system prompt + user query + retrieved chunks

**可验证标准**：
```bash
python assembler.py --query "费率是多少" --chunks chunk_001.json
# 输出：完整 prompt 字符串，可直接发给 LLM
```

## 4.7 能力 7：生成

**能做什么**：基于检索结果，调用 LLM 生成回答

**理解什么**：
- 为什么 RAG 生成：基于知识库回答，不是纯幻觉
- 生成约束：只基于检索结果回答，不编造
- 溯源：在回答中标注来源 chunk

**可验证标准**：
```bash
python generator.py --prompt "费率是多少" --chunks chunk_001.json
# 输出：带溯源的答案，如"根据费率表.md 第 1 条，USD/CNY 手续费 0.1%"
```
