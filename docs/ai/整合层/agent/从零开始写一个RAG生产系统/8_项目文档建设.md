---\n\n# §8 项目文档建设

**5W 速记卡**：
- **What**：README 结构 + 贡献指南 + 已知问题 + roadmap
- **Why**：文档是项目的门面，没有文档的项目没人用
- **Who**：想维护/贡献 RAG 项目的人
- **When**：项目稳定后补文档
- **Where**：README / 贡献指南 / 已知问题 / roadmap


**自测三问**：
1. 本文核心机制：文档四件套 = README + 贡献 + 问题 + 路线
2. 失效点：文档过时比没有更糟（要定期更新）
3. 与下篇衔接：项目文档 → 数据与事实声明


---

README 结构 + 贡献指南 + 已知问题 + roadmap。

## 8.1 README 结构

```markdown
# RAG 生产系统（从零手写）

## 是什么
从零手写一个生产级 RAG 系统，理解全链路原理。

## 快速开始
```bash
python pipeline.py "结算周期是 T+1 还是 T+2"
```

## 架构
- 文档加载 → 分块 → 向量化 → 检索 → 重排 → 生成

## 能力点
- 文档分块 / 向量化 / 向量存储 / 检索 / 重排 / 上下文组装 / 生成

## 演进路线
V1 白盒 → V2 换组件 → V3 服务化 → V4 生产级
```

## 8.2 贡献指南

- 分叉仓库 → 实现新能力 → 提交 PR
- 新能力需有：可验证标准 + 测试用例
- 代码规范：Python 3.10+，类型注解

## 8.3 已知问题

- 向量化依赖 OpenAI API（有成本/网络依赖）
- 无多轮对话支持
- 无评估闭环
- 无权限控制

## 8.4 Roadmap

| 版本 | 内容 | 状态 |
|---|---|---|
| V1 | 基础 RAG | ✅ 完成 |
| V2 | 混合检索 | 🔜 规划 |
| V3 | 服务化 API | 🔜 规划 |
| V4 | 生产级 | 🔜 规划 |
