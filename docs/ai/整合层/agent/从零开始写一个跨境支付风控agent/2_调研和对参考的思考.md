## 2.1 思考：调研什么

本篇目标：建立风控 agent 的**全谱系地图**——知道有哪些方向、各自解决什么问题、什么时候用哪个。

调研维度（延续 claude-code-cli 系列的 4 维）：

1. **架构**：风控 agent 怎么分层？编排引擎怎么选？
2. **能力**：风控 agent 需要什么能力？规则引擎 / LLM 判断 / 工具调用 / 多轮对话
3. **可复刻性**：参考对象能不能从零手写？代码复杂度如何？
4. **生产就绪**：参考对象离生产还有多远？

## 2.3 参考对象拆解

**规则引擎方向**：
- 参考：durable_rules / pyke / clpy
- 思路：从零手写规则引擎（规则匹配 + 例外处理）
- 优势：可控、可解释
- 劣势：僵化、无法处理异常模式

**LLM 判断方向**：
- 参考：LangChain Guardrails / NeMo-Guardrails
- 思路：用 LLM 做风险判断 + 规则引擎兜底
- 优势：灵活、能处理异常模式
- 劣势：慢、不可解释

**混合方向**：
- 参考：RAGFlow / LlamaIndex
- 思路：规则引擎 + LLM 混合，规则优先 + LLM 兜底
- 优势：兼顾速度与灵活
- 劣势：复杂、调试困难
