# §8 项目文档建设

## 一句话摘要

项目文档建设 的核心要点与实践指导。

**5W 速记卡**：
- **What**：风控 agent 项目文档
- **Why**：让开发者和用户快速了解系统
- **Who**：开发者和用户
- **When**：开发完系统后
- **Where**：本地开发环境和生产环境

**自测三问**：
1. 本文核心机制：文档建设 = README + 贡献 + 已知问题 + roadmap
2. 失效点：文档质量差 → 可维护性差
3. 与下篇衔接：项目文档 → 数据与事实声明

---

## 8.1 README

README 是什么：项目的入口文档——让开发者快速了解系统。

README 包含：
- 项目简介（风控 agent 是什么）
- 快速开始（怎么跑）
- 架构图（系统架构）
- 功能列表（核心能力）
- 贡献指南（怎么贡献）

## 8.2 贡献指南

贡献指南是什么：让其他人知道怎么贡献代码。

贡献指南包含：
- 开发环境搭建
- 代码规范
- 提交规范
- 测试规范

## 8.3 已知问题

已知问题是什么：项目当前的问题和限制。

已知问题包含：
- demo 级代码的限制
- 规则引擎的局限
- LLM 判断的不稳定
- 多轮对话的边界

## 8.4 Roadmap

Roadmap 是什么：项目的未来规划。

Roadmap 包含：
- 短期（规则引擎优化）
- 中期（LLM 判断优化）
- 长期（生产级风控系统）
