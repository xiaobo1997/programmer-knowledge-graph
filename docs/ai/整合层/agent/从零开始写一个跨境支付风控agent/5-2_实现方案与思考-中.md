# §5-2 实现方案与思考（中）：多轮对话 + 工具调用 + 权限分级

实现方案与思考（中） 的核心要点与实践指导。

**5W 速记卡**：
- **What**：风控 agent 从零实现（中）——多轮对话 + 工具调用 + 权限分级

## 5.3 多轮对话（追问澄清 → 确认风险 → 决策放行/拦截）

**多轮对话是什么？**——用户提问 → 意图不明确 → 追问澄清 → 确认风险 → 决策放行/拦截。

多轮对话做什么：
- 用户提问 → 意图理解
- 意图不明确 → 追问澄清
- 意图明确 → 执行动作（拦截/放行/人工审核）

多轮对话不做什么：
- 不做知识库检索（检索是 RAG 的事）
- 不做权限检查（权限是策略层的事）

**多轮对话的实现**：

```python
# risk_engine.py - 多轮对话
def multi_turn_dialogue(query, history):
    # 意图理解
    intent = understand_intent(query)
    
    # 意图不明确时追问澄清
    if intent == "unclear":
        return clarify(query, history)
    
    # 意图明确时执行动作
    if intent == "risk_check":
        return risk_check(query, history)
    
    # 可疑交易做多轮确认
    if intent == "suspicious":
        return confirm_risk(query, history)
```

**追问澄清的模式**：

| 模式 | 触发条件 | 追问内容 |
|---|---|---|
| 金额不明确 | 金额缺失 | 请提供交易金额 |
| 币种不明确 | 币种缺失 | 请提供交易币种 |
| 国家不明确 | 国家缺失 | 请提供交易国家 |
| 渠道不明确 | 渠道缺失 | 请提供交易渠道 |

## 5.4 工具调用（查黑名单/查交易历史/查合规政策）

**工具调用是什么？**——查黑名单/查交易历史/查合规政策。

工具调用做什么：
- 查黑名单（命中黑名单 → 高风险）
- 查交易历史（历史异常 → 高风险）
- 查合规政策（合规检查 → 低风险）

工具调用不做什么：
- 不做风险判断（工具只返回数据，不做判断）
- 不做权限检查（工具调用前需要权限检查）

**工具调用的实现**：

```python
# tools.py - 工具定义
def query_blacklist(user_id):
    """查黑名单"""
    return user_id in BLACKLIST

def query_transaction_history(user_id):
    """查交易历史"""
    return get_transactions(user_id)

def query_compliance_policy(country):
    """查合规政策"""
    return COMPLIANCE.get(country, {})
```

## 5.5 权限分级（L0-L3 + HITL 决策树）

**权限分级是什么？**——L0-L3 + HITL 决策树。

权限分级做什么：
- L0 只读（查数据）
- L1 写业务数据（标记风险）
- L2 外部副作用（拦截交易）
- L3 系统级（放行人工审核）

权限分级不做什么：
- 不做风险判断（权限只控制动作，不做判断）
- 不做审计日志（权限检查后需要审计）

**权限分级的实现**：

```python
# permissions.py - 权限分级
def check_permission(action, risk_level):
    """权限检查"""
    if action == "query":
        return "L0"  # 只读
    elif action == "mark":
        return "L1"  # 写业务数据
    elif action == "block":
        return "L2"  # 拦截交易
    elif action == "approve":
        return "L3"  # 放行人工审核
    
    # HITL 决策树
    if risk_level == "critical":
        return "HITL_REQUIRED"  # 需要人工审批
    elif risk_level == "high":
        return "HITL_REQUIRED"  # 需要人工审批
    else:
        return "AUTO"  # 自动执行
```

**HITL 决策树**：

| 风险等级 | HITL 必要性 | 审批人 | 决策权 |
|---|---|---|---|
| L0 只读 | ❌ 不需要 | - | agent 自动 |
| L1 业务 | ⚠️ 抽样（10%）| 业务 owner | agent 自动 + 事后审计 |
| L2 外部 | ✅ 必审批（实时）| 业务 owner | 人工实时审批 |
| L3 系统 | ✅✅ 双人审批（实时）| 业务 + 技术 owner | 人工双人审批 |

## 5.6 上下文组装与生成（带来源）

**上下文组装是什么？**——把规则结果 + LLM 判断 + 工具结果组装成 prompt。

上下文组装做什么：
- 组装规则结果
- 组装 LLM 判断
- 组装工具结果
- 注入对话历史

上下文组装不做什么：
- 不做风险判断（组装只是准备数据）
- 不做动作执行（组装后需要动作执行）

**上下文组装的实现**：

```python
# context.py - 上下文组装
def assemble_context(rules_result, llm_result, tools_result, history):
    """上下文组装"""
    context = {
        "rules": rules_result,
        "llm": llm_result,
        "tools": tools_result,
        "history": history,
    }
    return context
```

## 5.7 评估（准确率/召回率/人工审核率）

**评估是什么？**——评估风控 agent 的效果。

评估做什么：
- 准确率（正确拦截的比例）
- 召回率（正确识别风险的比例）
- 人工审核率（需要人工审核的比例）

评估不做什么：
- 不做风险判断（评估只衡量效果，不做判断）
- 不做权限检查（评估不控制权限）

**评估的实现**：

```python
# evaluate.py - 评估
def evaluate(rules_result, llm_result, actual_risk):
    """评估"""
    accuracy = calculate_accuracy(rules_result, actual_risk)
    recall = calculate_recall(llm_result, actual_risk)
    hitl_rate = calculate_hitl_rate(rules_result, llm_result)
    return accuracy, recall, hitl_rate
```

## 5.8 组装（命令级）+ 5.9 结果验收

**组装是什么？**——把各个文件组装成完整的系统。

组装做什么：
- CLI 入口 → 风险判断 → 动作执行 → 审计日志
- 命令级组装（最小可用）

组装不做什么：
- 不做风险判断（组装只是连接各模块）
- 不做权限检查（组装不控制权限）

**组装的实现**：

```python
# main.py - 组装
def main():
    """主入口"""
    # 1. 交易输入
    transaction = cli_input()
    
    # 2. 规则引擎
    rules_result = risk_engine(transaction)
    
    # 3. LLM 判断（规则不够时）
    llm_result = llm_judge(transaction, rules_result)
    
    # 4. 动作执行
    action = execute_action(llm_result)
    
    # 5. 审计日志
    audit_log(transaction, rules_result, llm_result, action)
    
    # 6. 输出
    return action
```

**结果验收**：
- 最小闭环能跑通（交易 → 风险判断 → 动作）
- 规则引擎能匹配（命中规则 → 返回风险等级）
- LLM 判断能覆盖异常（规则不够时 → LLM 判断）
- 多轮对话能追问（意图不明确 → 追问澄清）
- 工具调用能查数据（查黑名单/查交易历史/查合规政策）
- 权限分级能控制动作（L0-L3 + HITL 决策树）
- 审计日志能记录（记录完整决策依据）
