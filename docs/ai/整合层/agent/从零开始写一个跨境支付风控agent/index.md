# 从零开始写一个跨境支付风控 agent

> **系列**：从零写一个「跨境支付风控 agent」（整合层 demo 工程）

> **业务场景**：跨境支付风控——交易进入风控系统后，agent 自动判断风险等级 + 触发对应动作（拦截/放行/人工审核）
> **目标读者**：想动手做风控 agent 的工程师（有支付系统基础）
> **参考对象**：payment-rag-agent（知识库问答）+ claude-code-cli（agent 框架）

## 📚 学习路线（先理解门道，再写代码）

> 写作顺序不是从 §1 开始，而是先建立风控 agent 全景认知，再逐段推进。
> 每一段对应一个「搞懂的问题」，搞懂了再写。

| 阶段 | 搞懂的问题 | 对应章节 |
|---|---|---|
| ① 全景 | 风控 agent 是什么？为什么需要 agent 做风控？ | §1 + §2 |
| ② 原理 | 规则引擎怎么匹配？LLM 怎么判断风险？ | §3（原理部分） |
| ③ 环节 | 规则/对话/工具/权限各环节解决什么问题？ | §3 + §5 |
| ④ 动手 | 最小闭环怎么跑通？每个环节代码怎么组织？ | §5 |
| ⑤ 演进 | demo 到生产差在哪？风控系统 + agent 决策怎么融合？ | §6 + §10 |
| ⑥ 沉淀 | 文档怎么建设？参考资料怎么留？ | §8 + §9 |

**先理解的核心概念（每个都要能用自己的话讲出来）**：
- [ ] 风控 agent 是什么、为什么需要（规则引擎无法覆盖的异常模式）
- [ ] 规则引擎原理（规则匹配 + 例外处理）
- [ ] LLM 风险判断（多轮对话 + 追问澄清）
- [ ] 工具调用（查黑名单/查交易历史/查合规政策）
- [ ] 权限分级（L0-L3 + HITL 决策树）
