# §8 项目文档建设

> **系列**：从零开始写一个 claude-code-cli（整合层 demo 工程）
> **说明**：项目文档 = 读者上手的第一入口，也是项目可持续的基础。本 demo 虽小，文档体系照做（麻雀虽小五脏俱全）。

---

## 8.1 文档体系总览

```
cli-agent/（代码仓库）
├── README.md          ← 项目门面（目的/快速开始/命令/FAQ）
├── 需求.md            ← 四件套 1：为什么做 + 验收（内部管理）
├── specs.md           ← 四件套 2：行为契约（Requirement + Scenario）
├── 实施计划.md         ← 四件套 3：决策 + 任务（内部管理）
├── 交付报告.md         ← 四件套 4：验收结果（内部管理）
└── wiki/              ← 9 段文档（对外，学习路径）
    ├── 0_导读-全景.md
    ├── 1_为什么写.md ~ 10_Trade-off.md
    └── code-link.md
```

**两层文档**：
1. **对外（读者）**：README + wiki（9 段）——讲"这是什么 + 怎么学 + 怎么跑"
2. **对内（管理）**：四件套——讲"为什么做 + 验收标准"（协作流程用，不对外）

## 8.2 README.md 结构

```markdown
# cli-agent：从零写一个 CLI Agent（学习 demo）

> 一个麻雀虽小五脏俱全的 CLI agent——6 工具 + ReAct Loop + 5 层权限 + 会话恢复。

## 快速开始（3 分钟跑通）
1. 环境准备（Python 3.10+ / pip install requests / API key）
2. 最小闭环（写 2 个文件 → python main.py）
3. 完整功能（工具 + 权限 + 会话）

## 功能一览
| 命令 | 说明 |
|---|---|
| python main.py "任务" | 单次模式 |
| python main.py | 交互模式 |
| python main.py --resume | 恢复会话 |

## 文档导航
- wiki/0_导读-全景.md（学习路径）
- 6 大工具说明
- 5 层权限说明

## 已知问题 / 局限
- 无 MCP / 无并发 / 权限简单（详见 wiki §7）

## License
MIT
```

## 8.3 贡献指南（如何加一个工具）

```markdown
## 如何加一个工具

1. 在 tools/ 新建 xxx.py：
   ```python
   from . import Tool, register

   @register
   class XxxTool(Tool):
       name = "Xxx"
       description = "xxx 功能"
       parameters = {...}
       def handler(self, **kwargs): ...
   ```
2. 测试：python -c "from tools import TOOL_REGISTRY; print(TOOL_REGISTRY['Xxx'])"
3. 更新 README 功能一览 + specs.md（加 Requirement + Scenario）
```

**为什么这么设计**：注册表模式让扩展 = 加文件，不改核心——这是刻意展示的扩展性设计。

## 8.4 已知问题清单（诚实）

| # | 问题 | 影响 | 处理 |
|---|---|---|---|
| 1 | 权限用字符串匹配 | 危险命令检测不精确（如 `rm -rf /tmp/x` 变体）| 生产用正则 + 沙箱 |
| 2 | 无 MCP | 只能调 6 内置工具 | 生产接 MCP |
| 3 | 上下文压缩简单 | 长会话信息损失 | 生产用 LLM 摘要 |
| 4 | 单提供商 | 只支持 OpenAI 兼容 | 生产多云 |
| 5 | 无并发 | 单任务顺序执行 | 生产 SubAgent |

## 小结

文档建设原则：**对外讲清楚（README + wiki），对内管清楚（四件套），扩展有指南（加工具教程），局限诚实列（已知问题）**——即使 demo 也照做，因为文档习惯是工程素养的一部分。
