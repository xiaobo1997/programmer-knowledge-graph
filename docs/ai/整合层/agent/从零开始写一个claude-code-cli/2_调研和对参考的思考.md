## 2.2 claude-code 怎么工作（拆解）

### 2.2.1 产品形态

**claude-code 是什么**：终端里的 agentic coding 工具——用自然语言交互，能读代码库、执行任务、处理 git 工作流。

**技术底座**（来自 README 徽章）：**Node.js 18+**，npm 分发。

**安装方式**：curl 脚本 / homebrew / winget / npm（官方推荐 curl，npm 已 deprecated）。

### 2.2.2 第一手能力面（来自 `claude --help`，2026-08-19 实测）

**核心选项**（能力分组）：

| 能力域 | 选项 | 说明 |
|---|---|---|
| **会话** | `-c, --continue` / `--session-id` / `--teleport` / `--resume` | 继续上次 / 指定会话 / 恢复 |
| **非交互** | `-p, --print` | 一次性输出 |
| **工具控制** | `--tools` / `--allowedTools` / `--disallowedTools` / `--add-dir` | 指定可用工具 / 白名单 / 黑名单 / 额外目录 |
| **权限** | `--allow-dangerously-skip-permissions` / `--permission-mode` | 跳过权限检查（危险）/ 权限模式 |
| **模型** | `--model` / `--effort` | 模型选择 / 努力级别 |
| **MCP** | `--mcp-config` / `--strict-mcp-config` / `mcp` 子命令 | MCP 服务器配置 |
| **Agent** | `--agent` / `--agents` / `agents` 子命令 / `--bg` | 自定义 agent / 后台 agent |
| **插件** | `plugin` 子命令 | 插件管理 |
| **工作流** | `-w, --worktree` / `--tmux` | git worktree 隔离 |
| **设置** | `--settings` / `--setting-sources` / `--system-prompt` | 配置加载 |
| **调试** | `-d, --debug` / `--debug-file` / `doctor` | 调试 / 健康检查 |
| **Auth** | `auth` / `setup-token` | 认证 |

### 2.2.3 核心机制（从官方文档 + 仓库推断）

**Agent Loop（ReAct 模式）**：
```
用户输入 → LLM 思考（Reason）→ 选择工具（Act）→ 工具执行 → 结果返回 → LLM 继续思考 → ...直到任务完成
```

**6 大核心工具**（用户列出的标准集）：
1. **ReadFile**：读取文件内容
2. **WriteFile**：写文件
3. **EditFile**：精确编辑文件（替换指定内容）
4. **Bash**：执行 shell 命令
5. **Glob**：按模式找文件
6. **Grep**：搜索文件内容

**权限控制**（5 层纵深防御）：
```
L1 工具白名单（默认只有安全工具）
L2 目录边界（只能访问指定目录，--add-dir 扩展）
L3 命令黑名单（危险命令拦截，如 rm -rf）
L4 危险操作拦截（自动检测危险命令并提示）
L5 人工确认（高风险操作需要用户同意）
```

**上下文管理**：
- `--autocompact`：自动压缩窗口（100k-1M tokens）
- 跨会话记忆（CLAUDE.md / auto-memory）

**扩展机制**：
- **Slash Command**：`/命令`（/bug /doctor 等）
- **Skill 技能包**：`--disable-slash-commands` 选项暗示存在技能系统
- **Hook 钩子**：生命周期事件
- **MCP**：挂载任意符合 MCP 规范的外部工具
- **SubAgent**：`--agent` / `--agents` 自定义 agent
- **Git Worktree**：`-w` 并行隔离

## 2.3 能力点拆解表（复刻决策）

| # | 能力 | 参考实现 | 我们复刻吗 | 为什么 |
|---|---|---|---|---|
| 1 | **6 大核心工具**（ReadFile/WriteFile/EditFile/Bash/Glob/Grep）| claude-code 内置 | ✅ **复刻** | 核心能力，能独立验证（不依赖 LLM）|
| 2 | **Agent Loop（ReAct）** | claude-code 主循环 | ✅ **复刻** | 核心能力，理解 agent 如何自主循环 |
| 3 | **MCP 协议** | `mcp` 子命令 / MCP 规范 | ⚠️ **简化** | 完整 MCP 实现量大；demo 做一个"工具注册表"模拟 MCP 概念 |
| 4 | **Skill 技能包** | 官方技能系统 | ⚠️ **简化** | 做一个简单的"技能目录"（预置 prompt 片段）|
| 5 | **Slash Command** | `/命令` | ✅ **复刻** | 简单（命令注册表 + 分发）|
| 6 | **Hook 生命周期钩子** | 官方 hooks | ⚠️ **简化** | 做关键 hook（PreToolUse / PostToolUse / SessionStart）|
| 7 | **5 层权限防御** | 官方权限系统 | ✅ **复刻** | 核心安全能力，demo 版可简化但保留层级 |
| 8 | **上下文压缩** | `--autocompact` | ⚠️ **简化** | 做简单的 token 计数 + 摘要压缩 |
| 9 | **跨会话记忆** | CLAUDE.md / auto-memory | ⚠️ **简化** | 做会话 JSON 持久化（resume 功能）|
| 10 | **SubAgent 子任务** | `--agent` / `agents` | ⚠️ **跳过**（demo 版）| 复杂度高，影响核心学习目标 |
| 11 | **Git Worktree** | `-w` | ❌ **跳过** | 与核心学习目标无关 |
| 12 | **Agent Teams** | 官方 | ❌ **跳过** | 高级特性，超出 demo 范围 |
| 13 | **MCP 挂载** | `--mcp-config` | ⚠️ **简化** | 做一个内置的"模拟 MCP server"展示概念 |

## 2.4 复刻范围决策（总结）

**复刻（5 项）**：6 工具 + Agent Loop + Slash Command + 5 层权限 + 会话持久化（resume）

**简化（5 项）**：MCP（注册表模拟）+ Skill（预置 prompt）+ Hook（关键 3 个）+ 上下文压缩（token 计数 + 摘要）+ MCP 挂载（内置模拟）

**跳过（3 项）**：SubAgent + Git Worktree + Agent Teams——**复杂度高且与核心学习目标无关**

**为什么这么决策**：
- **核心目标 = 理解 Agent 工程化**（工具调用 + 循环 + 权限 + 上下文）——复刻项都围绕这个
- **简化项** = 展示概念但不追求完整实现（"麻雀虽小五脏俱全"）
- **跳过项** = 避免被次要特性拖累（分而治之：先学核心，扩展留未来）

## 2.5 技术选型初判（留给 §3 展开）

- **语言**：Python 3（简单 + 易读 + AI 生态）vs Node.js（对齐官方）——§3 详谈
- **LLM 调用**：OpenAI 兼容 API 或 Anthropic API（demo 用兼容接口，可切换）
- **CLI 框架**：argparse（Python 标准库）vs typer/click——§3 详谈
- **依赖最小化**：核心只用标准库 + requests（减少学习负担）

---

## 小结

调研结论：claude-code 的能力面非常丰富（242 行 help 输出），但**核心学习价值集中在 5 个复刻项**（工具 + Loop + 权限 + 命令 + 会话）。demo 采用"复刻核心 + 简化扩展 + 跳过高级"策略——**麻雀虽小五脏俱全**，2-3 周能完成且学到 Agent 工程化核心。
