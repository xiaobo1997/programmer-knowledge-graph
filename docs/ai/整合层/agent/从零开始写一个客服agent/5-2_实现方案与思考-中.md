实现方案与思考（中） 的核心要点与实践指导。

- **What**：客服 agent 从零实现（中）——多轮对话 + 工具调用 + 权限分级

## 5.3 多轮对话（追问澄清 → 确认意图 → 执行动作）

**多轮对话是什么？**——用户提问 → 意图不明确 → 追问澄清 → 确认意图 → 执行动作。

多轮对话做什么：
- 用户提问 → 意图理解
- 意图不明确 → 追问澄清
- 意图明确 → 执行动作（查订单/查费率/创建工单）

多轮对话不做什么：
- 不做知识库检索（检索是 RAG 的事）
- 不做权限检查（权限是策略层的事）

**多轮对话的实现**：

```python
# dialogue.py - 多轮对话
def multi_turn_dialogue(query, history):
    # 意图理解
    intent = understand_intent(query)
    
    # 意图不明确时追问澄清
    if intent == "unclear":
        return clarify(query, history)
    
    # 意图明确时执行动作
    if intent == "query_order":
        return query_order(query, history)
    
    # 可疑问题做多轮确认
    if intent == "suspicious":
        return confirm_intent(query, history)
```

**追问澄清的模式**：

| 模式 | 触发条件 | 追问内容 |
|---|---|---|
| 订单号不明确 | 订单号缺失 | 请提供订单号 |
| 时间不明确 | 时间缺失 | 请提供交易时间 |
| 币种不明确 | 币种缺失 | 请提供交易币种 |
| 状态不明确 | 状态缺失 | 请提供交易状态 |

## 5.4 工具调用（查订单/查费率/查结算/创建工单）

**工具调用是什么？**——查订单/查费率/查结算/创建工单。

工具调用做什么：
- 查订单（交易状态）
- 查费率（费率表）
- 查结算（结算规则）
- 创建工单（转人工）

工具调用不做什么：
- 不做知识库检索（工具只查外部数据）
- 不做权限检查（工具调用前需要权限检查）

**工具调用的实现**：

```python
# tools.py - 工具定义
def query_order(order_id):
    """查订单"""
    return get_order(order_id)

def query_rate(currency):
    """查费率"""
    return RATES.get(currency, {})

def query_settlement(order_id):
    """查结算"""
    return get_settlement(order_id)

def create_ticket(query):
    """创建工单"""
    return create_ticket(query)
```

## 5.5 上下文组装与生成（带来源）

**上下文组装是什么？**——把 RAG 结果 + 工具结果组装成 prompt。

上下文组装做什么：
- 组装 RAG 结果
- 组装工具结果
- 注入对话历史
- 生成带来源的回答

上下文组装不做什么：
- 不做风险判断（组装只是准备数据）
- 不做动作执行（组装后需要动作执行）

**上下文组装的实现**：

```python
# context.py - 上下文组装
def assemble_context(rag_result, tools_result, history):
    """上下文组装"""
    context = {
        "rag": rag_result,
        "tools": tools_result,
        "history": history,
    }
    return context
```

## 5.6 评估（准确率/召回率/人工审核率）

**评估是什么？**——评估客服 agent 的效果。

评估做什么：
- 准确率（正确回答的比例）
- 召回率（知识库命中比例）
- 人工审核率（需要人工审核的比例）

评估不做什么：
- 不做风险判断（评估只衡量效果）
- 不做权限检查（评估不控制权限）

**评估的实现**：

```python
# evaluate.py - 评估
def evaluate(rag_result, llm_result, actual_answer):
    """评估"""
    accuracy = calculate_accuracy(llm_result, actual_answer)
    recall = calculate_recall(rag_result, actual_answer)
    hitl_rate = calculate_hitl_rate(rag_result, llm_result)
    return accuracy, recall, hitl_rate
```

## 5.7 组装（命令级）+ 5.8 结果验收

**组装是什么？**——把各个文件组装成完整的系统。

组装做什么：
- CLI 入口 → RAG 检索 → LLM 生成 → 动作执行 → 审计日志
- 命令级组装（最小可用）

组装不做什么：
- 不做风险判断（组装只是连接各模块）
- 不做权限检查（组装不控制权限）

**组装的实现**：

```python
# main.py - 组装
def main():
    """主入口"""
    # 1. 用户提问
    query = cli_input()
    
    # 2. RAG 检索
    rag_result = rag_engine(query)
    
    # 3. LLM 生成
    llm_result = llm_generate(query, rag_result)
    
    # 4. 动作执行
    action = execute_action(llm_result)
    
    # 5. 审计日志
    audit_log(query, rag_result, llm_result, action)
    
    # 6. 输出
    return action
```

**结果验收**：
- 最小闭环能跑通（用户提问 → RAG 检索 → LLM 生成 → 回答）
- RAG 能检索（命中知识库 → 返回来源）
- LLM 能生成（带来源的回答）
- 多轮对话能追问（意图不明确 → 追问澄清）
- 工具调用能查数据（查订单/查费率/查结算/创建工单）
- 权限分级能控制动作（L0-L3 + HITL 决策树）
- 审计日志能记录（记录完整决策依据）
