- **What**：客服 agent 生态全景调研

## 2.1 思考：调研什么

本篇目标：建立客服 agent 的**全谱系地图**——知道有哪些方向、各自解决什么问题、什么时候用哪个。

调研维度（延续 claude-code-cli 系列的 4 维）：

1. **架构**：客服 agent 怎么分层？编排引擎怎么选？
2. **能力**：客服 agent 需要什么能力？多轮对话 / RAG / 工具调用
3. **可复刻性**：参考对象能不能从零手写？代码复杂度如何？
4. **生产就绪**：参考对象离生产还有多远？

## 2.3 参考对象拆解

**RAG 方向**：
- 参考：awesome-rag / RAGFlow / LlamaIndex
- 思路：从零手写 RAG（文档加载 → 分块 → 向量化 → 检索 → 生成）
- 优势：可控、可解释
- 劣势：功能有限

**多轮对话方向**：
- 参考：LangChain / OpenAI Assistants API
- 思路：用 LLM 做多轮对话 + 状态管理
- 优势：灵活、能处理复杂场景
- 劣势：不可解释、调试困难

**工具调用方向**：
- 参考：LangChain / LlamaIndex
- 思路：LLM 调用外部工具（查订单/查费率/查结算）
- 优势：灵活、能集成现有系统
- 劣势：需要维护工具定义
