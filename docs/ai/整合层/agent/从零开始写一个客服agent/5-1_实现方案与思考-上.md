## 5.0 最小闭环（2 文件：用户提问 → 知识库检索 → LLM 生成）

**最小闭环是什么？**——只保留客服 agent 最核心的环节：

```
用户提问 → 知识库检索 → LLM 生成 → 带来源的回答
```

**为什么从最小闭环开始？**——先跑通一个能工作的闭环，再逐步加能力。最小闭环只有 2 个文件：
1. `rag_engine.py`：RAG 检索 + LLM 生成
2. `answer.py`：答案组装（带来源）

**最小闭环的局限**：不能做多轮对话、不能查外部数据、不能审计。但这不影响"跑通"——先跑通，再完善。

**最小闭环的实现要点**：
- RAG 检索：Python 字典 + 余弦相似度（零依赖）
- LLM 生成：requests 调用 OpenAI API（唯一外部依赖）
- 答案组装：打印日志（demo 级）
- 权限分级：代码里 if/else（demo 级）
- 审计日志：写文件（demo 级）

## 5.1 全局地图（自上而下：7 文件 / 5 步数据流）

**全局地图是什么？**——从零实现时，先画一张图——知道要写多少文件、每一步做什么。

```mermaid
    C --> D[\"上下文组装<br/>问题 + 上下文\"]

```

**7 文件 / 5 步数据流**：

| # | 文件 | 职责 | 数据 |
|---|---|---|---|
| 1 | `cli.py` | 入口：用户提问 | 用户输入 |
| 2 | `rag_engine.py` | RAG 检索 + LLM 生成 | 检索结果 + LLM 回答 |
| 3 | `chunker.py` | 分块 | 文档分块 |
| 4 | `vectorizer.py` | 向量化 | TF-IDF 向量 |
| 5 | `searcher.py` | 检索 | Top-K 相似 chunk |
| 6 | `answer.py` | 答案组装 | 带来源的回答 |
| 7 | `audit.py` | 审计日志 | 审计记录 |

**5 步数据流**：
1. 用户提问 → 意图理解（解析用户输入）
2. 意图理解 → 知识库检索（向量化 + 检索）
3. 知识库检索 → 上下文组装（组装 prompt）
4. 上下文组装 → LLM 生成（生成回答）
5. LLM 生成 → 审计日志（记录决策）

## 5.2 知识库构建与分块

**知识库构建是什么？**——把业务文档沉淀成知识库，让 agent 检索。

知识库构建包含：
- 文档加载（费率表/结算规则/拒付流程）
- 分块（递归字符分块 500字+50重叠）
- 向量化（TF-IDF 词频向量）
- 索引（内存向量表 + 文档映射）

**知识库构建的实现**：

```python
# chunker.py - 分块
def chunk_document(doc, chunk_size=500, overlap=50):
    """文档分块"""
    chunks = []
    for i in range(0, len(doc), chunk_size - overlap):
        chunk = doc[i:i + chunk_size]
        chunks.append(chunk)
    return chunks
```
