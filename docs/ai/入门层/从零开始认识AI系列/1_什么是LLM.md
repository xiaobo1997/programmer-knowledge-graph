# 什么是 LLM：从"预测下一个词"到"能干活的大脑"

> 一句话摘要：LLM 是一个被训练出来"能说人话、能写代码"的大模型——它的本质是"预测下一个词"，但当你把足够多的参数、足够多的数据、足够聪明的训练方法叠在一起，它就表现出了接近人类的理解和推理能力。**理解 LLM 的能力边界，是理解整个 AI 技术栈的地基。**

**本文核心**：LLM = 超大规模"下一词预测器"——能力来自规模效应（参数×数据×算力）的涌现，不是魔法；四个原生缺陷（知识截止/算不准/无记忆/不能行动）精确对应四大工程组件（RAG/工具调用/记忆系统/Agent），AI 应用架构师第一步是判断"踩了哪个不能"。

## 1. 背景：为什么需要理解 LLM

2024 年到 2026 年，AI 领域每天冒出新名词：Agent、Harness、MCP、RAG、Subagent、Eval……这些词让初学者眼花缭乱。

但有一个底层事实：**所有这些概念，都建立在 LLM 之上。**

- Agent 是"套了工具和循环的 LLM"
- Harness 是"让 LLM 能安全可靠干活的基础设施"
- MCP 是"让 LLM 能调用外部工具的标准化协议"

如果不懂 LLM 是什么、能做什么、不能做什么，你学后面的概念就是在沙滩上盖楼——每个词都认识，但拼不起来。

## 2. 核心内容：LLM 是什么 + 怎么工作

### 2.1 一句话定义

> **LLM（Large Language Model，大语言模型）= 一个被训练出来"预测下一个词"的巨型神经网络。**

听起来很朴素，但这是理解一切的钥匙。

它的工作机制是：给定一段文本，预测下一个最可能出现的词（token）。

```
输入："今天天气很"
输出："好"（概率 0.6）/ "糟"（概率 0.3）/ "冷"（概率 0.1）...
```

你日常用的 ChatGPT、Claude、DeepSeek，本质上都是这个机制——只不过参数规模大（几百亿到上万亿）、训练数据多（整个互联网）、训练方法巧（对齐人类偏好）。

**这就是"预测下一个词"的魔力**：当你把"预测"重复几万亿次，模型在统计规律里学会了语法、知识、逻辑甚至"常识"。这不是魔法，是规模效应。

### 2.2 训练三阶段：LLM 是怎么来的

```mermaid
flowchart LR
    A[预训练<br/>学语言规律] --> B[SFT 监督微调<br/>学对话格式]
    B --> C[RLHF 人类反馈<br/>学"讨人喜欢"]
    C --> D[可用的 LLM]
```

| 阶段 | 干什么 | 数据 | 结果 |
|---|---|---|---|
| **预训练** | 预测下一个词，学语言统计规律 | 整个互联网的文本（万亿 token） | 一个"会接话"的模型 |
| **SFT**（监督微调） | 学"问→答"格式，模仿人类回答 | 人工标注的问答对 | 一个"会回答"的模型 |
| **RLHF**（人类反馈强化学习） | 按人类偏好排序，学"什么回答更好" | 人类对回答的评分 | 一个"讨人喜欢"的模型 |

**关键认知**：模型的能力上限主要由预训练决定（数据 + 算力），SFT 和 RLHF 是"调教"它变得更可用，但不会凭空增加知识。

### 2.3 三个必须懂的关键概念

**Token（词元）**——模型处理的最小文本单位

- 一个汉字 ≈ 1-2 token，一个英文单词 ≈ 1-3 token
- **计费和上下文窗口都按 token 算**，不是按字数
- 例：1000 个汉字的文章 ≈ 1500-2000 token

**Context（上下文）**——模型当前能"看到"的所有内容

- 系统提示 + 你的输入 + 历史消息 + 工具返回结果
- 每次调用，模型看到的都是"一份拼好的文本"

**Context Window（上下文窗口）**——模型一次能处理的最大 context

- Claude 200K、GPT 级别 128K、新模型已到 1M+
- 窗口越大 = 能一次塞进越多的文档/对话/工具结果

### 2.4 计费：为什么 AI 贵（或便宜）

```
输入 token（你发的内容）× 输入单价 + 输出 token（模型回的）× 输出单价
```

- 输出 token 通常比输入贵 3-4 倍
- 模型越强，单价越高；但开源模型可以自部署，成本可控
- **这是理解 Agent 成本的关键**：Agent 一次任务可能调用模型十几次，token 消耗是普通聊天的几十倍

## 3. 能力边界：LLM 能做什么、不能做什么

### 3.1 能做什么（很强）

- **语言生成**：写文章、写代码、翻译、总结
- **知识问答**：训练数据里学到的知识（截止到训练时间）
- **逻辑推理**：简单数学、逻辑题、代码调试（配合思维链更强）
- **角色扮演 / 对话**：能保持上下文连贯地对话

### 3.2 不能做什么（这四个"不能"是理解 AI 技术栈的关键）

| 不能 | 说明 | 谁来解决 | 关键追问 |
|---|---|---|---|
| **不知道训练截止后的事** | 训练数据有截止时间（cutoff），之后的事一概不知 | RAG（检索增强） | 检索错了怎么办？→ 溯源 + 置信度阈值 |
| **算不了精确数学** | 大数乘法、精确计算会出错（它是在"猜"） | Tool（计算器） | 为什么不直接训练？→ 架构性的：生成式模型不是计算器 |
| **记不住昨天的对话** | 每次调用都是独立的，无状态 | Memory（记忆系统） | 记忆放哪里？→ 外置存储，注入窗口 |
| **不能行动** | 只能生成文本，不能自己查库、发请求、操作电脑 | Agent Loop + Tool | 怎么停？→ 工具返回观察 + 终止条件判断 |

**典型场景**：
- 知识问答（踩"不知道"）→ RAG
- 代码生成（踩"算不准"）→ 工具调用（code interpreter）
- 长对话助手（踩"无记忆"）→ Memory 外置
- 自动运维/客服（踩"不能行动"）→ Agent Loop

### 3.3 与传统程序的对比

| 维度 | 传统程序 | LLM |
|---|---|---|
| 执行方式 | 确定性地执行指令 | 概率性地生成下一个 token |
| 可解释性 | 代码走读即可理解 | "黑箱"——只能观测输入输出 |
| 调试方式 | 打日志 + 断点 | 改 prompt / 调参数 / 换模型 |
| 适用边界 | 精确计算 / 确定性逻辑 | 模糊判断 / 模式识别 / 生成 |

### 3.4 典型使用场景

- **知识问答**：RAG 接入私有知识库，适合 FAQ/文档检索
- **代码生成**：IDE 插件/CI 中的代码补全，需要工具调用保证格式
- **长对话助手**：需要 Memory 外置维持上下文
- **自动化运维/客服**：Agent Loop + 权限闸门，不可直达生产

### 3.5 与传统 RAG 的区别

| 维度 | 传统 RAG | LLM + RAG |
|---|---|---|
| 查询理解 | 关键词匹配 | 语义理解 + 重写 |
| 召回 | 向量相似度 | 混合检索（向量+关键词+图谱） |
| 生成 | 拼接文档 | 基于检索的事实+模型推理 |

### 3.6 误区与不适用

**常见误区**：
- "模型越强越好"——选型看场景，不是排名
- "RAG 能根治幻觉"——RAG 只能降低不能消灭
- "上下文窗口越大越好"——U 形注意力下中间段被系统性低估

**不适用场景**：
- 精确计算（用计算器/代码）
- 实时数据（用联网工具）
- 高安全场景直接依赖模型输出（必须有人工闸门）

### 3.7 与传统搜索的区别

| 维度 | 传统搜索 | LLM + RAG |
|---|---|---|
| 结果形式 | 链接列表 | 直接回答 + 引用 |
| 理解能力 | 关键词匹配 | 语义理解 |
| 维护成本 | 索引引擎 | 知识库维护 + 检索调优 |

## 生产事故叙事（深度密度）

**2024 年某电商大促**：RAG 知识库的文档更新滞后，模型基于过期条款生成回答，客服系统连续 3 小时向用户承诺"7 天无理由退换"，实际活动规则已改为"仅 3 天"。根因：检索召回的是旧文档 + 没有置信度阈值拦截。止血方案：把置信度低于 0.7 的答案强制转人工，误报率 12% 但拦截了全部高风险回答。教训：**RAG 不是装了就安全——检索质量 + 置信度闸门缺一不可**。

## 4. 主流模型全景（选型视角）

### 4.1 闭源 vs 开源

| 阵营 | 代表 | 特点 | 适用 |
|---|---|---|---|
| **闭源 API** | Claude / GPT / Gemini / DeepSeek / GLM | 开箱即用、最强推理、按量付费 | 产品快速验证、追求效果 |
| **开源** | Llama / Qwen | 可自部署、数据不出内网、成本可控 | 数据敏感、长期成本优化 |

### 4.2 选模型看三件事（Agent 场景）

```
1. 推理能力    → 决定 Agent 的规划质量（能不能自己拆解任务）
2. 上下文长度  → 决定能塞多少工具结果/文档（Context Window）
3. 工具调用稳定性 → 决定 Function Calling 会不会抽风（输出格式稳不稳）
```

**注意**：做 Agent 时，模型"能不能稳定输出工具调用"比"文采好不好"重要得多——工具调用格式一错，Agent 就断了。

### 4.3 一个朴素的选型建议

- 验证想法 → 用闭源最强模型（效果优先）
- 上线稳定 → 按场景换成性价比模型（成本优先）
- 数据敏感 → 开源自部署（合规优先）

## 5. 一句话总结 + 5W 速记卡

### 5.1 一句话总结

> **LLM = 巨型"预测下一个词"网络。它强在语言和推理，弱在实时、精确、记忆、行动——AI 技术栈的所有概念，都是围绕它的能力边界搭脚手架。**

### 5.2 5W 速记卡

| W | 内容 |
|---|---|
| **What** | 被训练出来"能说人话/写代码"的大模型 |
| **Why** | 规模效应：预测下一个词，练出语言+知识+推理 |
| **Who** | Claude / GPT / DeepSeek / Llama / Qwen 等 |
| **When** | 2020 年 GPT-3 开启，2023+ 进入 Agent 时代 |
| **How** | 预训练 → SFT → RLHF 三阶段训练 |

## 核心带走

一句话复述：LLM = 预测下一个词的巨型神经网络。智能来自规模涌现，不是魔法。四个"不能"（实时/精确/记忆/行动）决定架构——RAG 补知识、工具补计算、Memory 补记忆、Agent 补行动。选型先判"踩了哪个不能"。

## tips

- 反直觉点：涌现不是"越大越好"——好上下文+开源小模型可以追平顶级生产 Agent 在基准上的表现（ACE 系统研究）
- 防御话术："LLM 是大脑不是身体，四个短板必须靠工程组件补——我们按'踩了哪个不能'决定架构"
- 考场应急：被问"大模型会不会取代程序员"→ "LLM 缺实时/精确/记忆/行动四能力，程序员工作从写代码变成设计脚手架+治理"

## 思考

- RAG vs 微调的选择标准能否更量化？——当前以"知识缺口 vs 行为缺口"二分，实际场景常有交叉（新领域+新格式），未来可引入"知识新鲜度×格式稳定性"二维矩阵
- Agent 场景下，四个"不能"的优先级是否固定？——按业务场景动态调整：客服场景"不能行动"优先，知识库场景"不知道"优先
