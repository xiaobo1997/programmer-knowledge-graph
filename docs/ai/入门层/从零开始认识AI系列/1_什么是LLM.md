# 什么是 LLM：从"预测下一个词"到"能干活的大脑"

> 一句话摘要：LLM 是一个被训练出来"能说人话、能写代码"的大模型——它的本质是"预测下一个词"，但当你把足够多的参数、足够多的数据、足够聪明的训练方法叠在一起，它就表现出了接近人类的理解和推理能力。**理解 LLM 的能力边界，是理解整个 AI 技术栈的地基。**

---

## 1. 背景：为什么需要理解 LLM

2024 年到 2026 年，AI 领域每天冒出新名词：Agent、Harness、MCP、RAG、Subagent、Eval……这些词让初学者眼花缭乱。

但有一个底层事实：**所有这些概念，都建立在 LLM 之上。**

- Agent 是"套了工具和循环的 LLM"
- Harness 是"让 LLM 能安全可靠干活的基础设施"
- MCP 是"让 LLM 能调用外部工具的标准化协议"

如果不懂 LLM 是什么、能做什么、不能做什么，你学后面的概念就是在沙滩上盖楼——每个词都认识，但拼不起来。

**本篇任务**：把 LLM 讲透——它怎么来的、怎么工作的、能力边界在哪、市面上有哪些主流选择。读完你能回答三个问题：

1. LLM 到底是什么（一句话）
2. 它为什么"看起来会思考"
3. 它不能做什么（这决定了为什么需要 Agent）

## 2. 核心内容：LLM 是什么 + 怎么工作

### 2.1 一句话定义

> **LLM（Large Language Model，大语言模型）= 一个被训练出来"预测下一个词"的巨型神经网络。**

听起来很朴素，但这是理解一切的钥匙。

它的工作机制是：给定一段文本，预测下一个最可能出现的词（token）。

```
输入："今天天气很"
输出："好"（概率 0.6）/ "糟"（概率 0.3）/ "冷"（概率 0.1）...
```

你日常用的 ChatGPT、Claude、DeepSeek，本质上都是这个机制——只不过参数规模大（几百亿到上万亿）、训练数据多（整个互联网）、训练方法巧（对齐人类偏好）。

**这就是"预测下一个词"的魔力**：当你把"预测"重复几万亿次，模型在统计规律里学会了语法、知识、逻辑甚至"常识"。这不是魔法，是规模效应。

### 2.2 训练三阶段：LLM 是怎么来的

```mermaid
flowchart LR
    A[预训练<br/>学语言规律] --> B[SFT 监督微调<br/>学对话格式]
    B --> C[RLHF 人类反馈<br/>学"讨人喜欢"]
    C --> D[可用的 LLM]
```

| 阶段 | 干什么 | 数据 | 结果 |
|---|---|---|---|
| **预训练** | 预测下一个词，学语言统计规律 | 整个互联网的文本（万亿 token） | 一个"会接话"的模型 |
| **SFT**（监督微调） | 学"问→答"格式，模仿人类回答 | 人工标注的问答对 | 一个"会回答"的模型 |
| **RLHF**（人类反馈强化学习） | 按人类偏好排序，学"什么回答更好" | 人类对回答的评分 | 一个"讨人喜欢"的模型 |

**关键认知**：模型的能力上限主要由预训练决定（数据 + 算力），SFT 和 RLHF 是"调教"它变得更可用，但不会凭空增加知识。

### 2.3 三个必须懂的关键概念

**Token（词元）**——模型处理的最小文本单位

- 一个汉字 ≈ 1-2 token，一个英文单词 ≈ 1-3 token
- **计费和上下文窗口都按 token 算**，不是按字数
- 例：1000 个汉字的文章 ≈ 1500-2000 token

**Context（上下文）**——模型当前能"看到"的所有内容

- 系统提示 + 你的输入 + 历史消息 + 工具返回结果
- 每次调用，模型看到的都是"一份拼好的文本"

**Context Window（上下文窗口）**——模型一次能处理的最大 context

- Claude 200K、GPT 级别 128K、新模型已到 1M+
- 窗口越大 = 能一次塞进越多的文档/对话/工具结果

### 2.4 计费：为什么 AI 贵（或便宜）

```
输入 token（你发的内容）× 输入单价 + 输出 token（模型回的）× 输出单价
```

- 输出 token 通常比输入贵 3-4 倍
- 模型越强，单价越高；但开源模型可以自部署，成本可控
- **这是理解 Agent 成本的关键**：Agent 一次任务可能调用模型十几次，token 消耗是普通聊天的几十倍

## 3. 能力边界：LLM 能做什么、不能做什么

### 3.1 能做什么（很强）

- **语言生成**：写文章、写代码、翻译、总结
- **知识问答**：训练数据里学到的知识（截止到训练时间）
- **逻辑推理**：简单数学、逻辑题、代码调试（配合思维链更强）
- **角色扮演 / 对话**：能保持上下文连贯地对话

### 3.2 不能做什么（这四个"不能"是理解 AI 技术栈的关键）

| 不能 | 说明 | 谁来解决 |
|---|---|---|
| **不知道今天发生什么** | 训练数据有截止时间（cutoff），之后的事一概不知 | RAG（检索增强） |
| **算不了精确数学** | 大数乘法、精确计算会出错（它是在"猜"） | Tool（计算器） |
| **记不住昨天的对话** | 每次调用都是独立的，无状态 | Memory（记忆系统） |
| **不能自主行动** | 只能生成文本，不能自己查库、发请求、操作电脑 | Agent Loop + Tool |

**⚠️ 这是本篇最重要的部分**：这 4 个"不能"不是缺陷，而是**设计边界**。整个 AI 技术栈（Agent/Harness/MCP/RAG）存在的意义，就是围绕这 4 个边界搭脚手架。

- LLM 不会查实时股价 → 给它一个 `search` 工具
- LLM 不会精确计算 → 给它一个 `calculator` 工具
- LLM 没有记忆 → 把历史对话重新塞进 prompt
- LLM 不能行动 → 用循环让它"想一步、做一步、看结果、再想"

**一句话**：LLM 是"大脑"，不是"身体"。大脑负责想，身体（工具/循环/记忆）负责干。这就是下一篇《为什么需要 Agent》的起点。

## 4. 主流模型全景（选型视角）

### 4.1 闭源 vs 开源

| 阵营 | 代表 | 特点 | 适用 |
|---|---|---|---|
| **闭源 API** | Claude / GPT / Gemini / DeepSeek / GLM | 开箱即用、最强推理、按量付费 | 产品快速验证、追求效果 |
| **开源** | Llama / Qwen | 可自部署、数据不出内网、成本可控 | 数据敏感、长期成本优化 |

### 4.2 选模型看三件事（Agent 场景）

```
1. 推理能力    → 决定 Agent 的规划质量（能不能自己拆解任务）
2. 上下文长度  → 决定能塞多少工具结果/文档（Context Window）
3. 工具调用稳定性 → 决定 Function Calling 会不会抽风（输出格式稳不稳）
```

**注意**：做 Agent 时，模型"能不能稳定输出工具调用"比"文采好不好"重要得多——工具调用格式一错，Agent 就断了。

### 4.3 一个朴素的选型建议

- 验证想法 → 用闭源最强模型（效果优先）
- 上线稳定 → 按场景换成性价比模型（成本优先）
- 数据敏感 → 开源自部署（合规优先）

## 5. 一句话总结 + 5W 速记卡

### 5.1 一句话总结

> **LLM = 巨型"预测下一个词"网络。它强在语言和推理，弱在实时、精确、记忆、行动——AI 技术栈的所有概念，都是围绕它的能力边界搭脚手架。**

### 5.2 5W 速记卡

| W | 内容 |
|---|---|
| **What** | 被训练出来"能说人话/写代码"的大模型 |
| **Why** | 规模效应：预测下一个词，练出语言+知识+推理 |
| **Who** | Claude / GPT / DeepSeek / Llama / Qwen 等 |
| **When** | 2020 年 GPT-3 开启，2023+ 进入 Agent 时代 |
| **How** | 预训练 → SFT → RLHF 三阶段训练 |

### 5.3 自测三问

1. LLM 的本质是什么？（预测下一个词）
2. 模型的能力上限主要由哪个阶段决定？（预训练）
3. 它不能做的四件事是什么？（实时/精确/记忆/行动）
