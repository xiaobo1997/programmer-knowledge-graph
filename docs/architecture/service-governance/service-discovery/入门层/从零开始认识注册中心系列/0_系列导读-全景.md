# 注册中心系列导读：从地址簿到高可用基座

> 入门层 10 篇导读。讲清系列定位、4 组关系、阅读路径、与相邻系列的关系——**不重复入门层定义**。

## 一、这个系列讲什么

微服务一多，「服务 A 怎么找到服务 B」立刻变难：IP 天天漂移、实例上下线频繁、人工配地址必然崩。本系列讲**注册中心这个治理基座**——从「为什么不能手动配地址」讲到 AP/CP 选型与高可用运维。机制与组件分工先划清——深度与泛化之间的取舍由两层系列完成：**ZooKeeper / Nacos / Eureka 等组件深挖归 middleware 域系列**（tips 互指），本系列讲跨实现的**治理机制**本身。

按 4 组组织——由浅入深的演进式结构：

```mermaid

    G1["组1:认知与模型"] --> G2["组2:三大机制<br/>注册/订阅/健康检查"]
```

认知模型 → 三大机制（注册/订阅/健康检查）→ 一致性与高可用 → 选型与运维。

## 二、4 组关系

```
第 1 组 认知与核心模型   ← 为什么需要 + 三要素模型
第 2 组 核心机制        ← 注册 / 订阅 / 健康检查（三大能力）
第 3 组 一致性与高可用   ← AP vs CP + 选主与同步
第 4 组 选型与实践      ← 对比矩阵 + 决策树 + 运维收束
```
