# 负载均衡是什么：从单点到多实例的流量治理

> 一句话：负载均衡是**把请求流量按策略分发到多个实例的机制**——多实例解决了容量，负载均衡解决了「容量怎么被公平且高效地用起来」。

> **本文核心**：负载均衡的本质是「多实例后的流量分配决策」。**机制链**：单点容量到顶 → 水平扩多实例 → 流量分发问题出现 → 引入均衡机制（位置 × 策略两个决策维度）→ 均匀/高效地消费集群容量。

## 一句话摘要

单机扛不住就加机器，加完机器多出一个新问题：**请求该打给谁**。负载均衡就是这个「分发决策」——它由两个独立决策构成：**放在哪一层**（硬件/L4/L7/客户端/服务网格，篇 2）与**按什么策略**（随机/轮询/哈希/最少活跃，篇 3-5）。均衡的目标不是绝对平均，是**按实例能力与状态高效消费集群容量**——「均匀」只是手段，「高效」才是目的。

## 一、为什么多实例不能没有均衡机制

三个实例裸奔的必然乱象：客户端写死第一个地址（其余实例吃灰）；DNS 轮询（缓存延迟 + 无健康感知，坏实例照收流量）；「轮流来」的朴素轮询（不考虑实例能力差异与实时负载）。**分发决策缺位 = 集群容量利用率随机 + 故障实例继续挨打**——负载均衡机制把「分发」从偶然变成治理：按策略分发、按健康剔除、按容量加权——这是流量治理从裸奔到体系的演进第一步。

## 二、均衡机制的两个决策维度

```mermaid
flowchart TD
    LB["负载均衡两个决策"] --> POS["位置:在哪一层分发<br/>L4/L7/客户端/网格(篇2)"]
    LB --> STR["策略:按什么规则选实例<br/>随机/轮询/哈希/活跃(篇3-5)"]
    POS --> EFF["效果:转发效率 vs 内容感知"]
    STR --> EFF2["效果:均匀性 vs 状态感知"]
    EFF + EFF2 --> GOAL["目标:高效消费集群容量"]
    style LB fill:#ffd3a5
    style GOAL fill:#a8e6a3
```

两个维度**正交且组合**：同一策略（如轮询）可以部署在任何位置；同一位置（如网关）可以配任意策略——「位置决定能力的边界（能不能看内容），策略决定分发的规则（怎么选实例）」。这个二维框架立住，后面每篇都是往某个格子里填细节。

## 三、与「服务路由」的区别：均匀分发 vs 定向分发

| 维度 | 负载均衡 | 服务路由（互指 service-routing） |
|---|---|---|
| 分发目标 | 摊开：全实例分摊流量 | 定向：引到指定子集（灰度/泳道） |
| 决策依据 | 容量与状态 | 元数据与规则 |
| 失败语义 | 尽量均匀 | 尽量精确 |

两者在调用链上串联（先路由筛选子集、再均衡选实例）——**路由是「缩小候选集」，均衡是「在候选集里选」**，视角型边界清晰，互指不重写。

## 四、典型场景与误区

**典型场景**：网关到后端的流量分发（L7 + 多策略）、RPC 客户端直连均衡（服务列表 + 客户端策略）、数据库读写代理（读写分离也是均衡的特例——写单点读多路）。

**误区与不适用**：① 均衡 = 绝对平均——加权与最少活跃类策略的存在就是承认「实例不平等」；② 有均衡器就不用健康检查——均衡与健康是两条链路（均衡选实例，健康管候选集，互指 service-discovery 篇 5）；③ 单实例也要上均衡器——机制服务于多实例，单点加均衡是纯开销。

## 五、💡 实战提示

- 💡 先选位置再选策略：位置错了策略再精也没用
- 💡 均衡效果要监控（实例间流量/QPS 分布），摊不匀的均衡是装饰
- 💡 任何策略都要配失败重选（选到的实例挂了怎么办，互指容错系列）

## 六、你们可能会问

**Q1：负载均衡器会不会成为单点？**
会——所以均衡器自身必须集群化（VIP/ECMP/Anycast 或 DNS 多地址），「均衡器的高可用」是部署的前置课题，不是选完策略再想的事。

**Q2：客户端均衡和服务端均衡怎么选？**
客户端（RPC 框架内置）少一跳、语言绑定；服务端（网关/LB 设备）语言无关、管控集中——按技术栈异构性与管控需求权衡（篇 2 展开四位置全景）。

**Q3：为什么不直接用 DNS 轮询？**
DNS 缓存让下线不生效、无健康检查、粒度粗——DNS 只适合「粗粒度、强容忍」场景，精细治理要专业均衡机制。

## 七、开放问题

- 服务网格把负载均衡下沉到 sidecar，「位置」维度出现了第四代形态（内核层 eBPF 加速），均衡机制的位置谱系仍在扩展。
- 按请求成本的均衡（成本感知路由）在异构算力（CPU/GPU 混布）场景兴起，「均匀」的定义在被 AI 负载重写。

## 📎 核心带走

- **核心一句话**：负载均衡 = 多实例后的分发决策机制，位置（在哪层）× 策略（怎么选）两个正交维度
- **机制链**：单点到顶 → 多实例 → 分发决策 → 位置 × 策略组合 → 高效消费集群容量
- **失效点/边界**：均衡不解决健康问题（候选集归健康检查管）；单实例无需均衡
