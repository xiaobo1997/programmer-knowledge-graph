# RPC 的负载均衡策略：调用方视角的选择算法

> **本文核心**：RPC 客户端的负载均衡——「从地址列表中选一个实例发起调用」。**机制链**：地址列表（服务发现产出）→ 负载均衡策略（随机/轮询/加权/一致性哈希/最少活跃）→ 选中实例 → 发起调用。RPC 的负载均衡是**客户端模式**（进程内选择，无需 LB 设备）——与网关/L4/L7 的服务端模式形成位置互补。策略机制深挖互指 load-balancing 系列。

> **本文核心**：五种策略的选型直觉——**随机**：无状态最简、统计均匀；**轮询**：顺序绝对均匀；**加权轮询（平滑加权）**：异构实例按能力配比分发；**一致性哈希**：同 key 同实例（会话/缓存亲和）；**最少活跃**：按实例当前并发数选最闲（自适应慢实例）。**机制链**：地址列表 → 策略选择 → 失败重选联动上下游（failover 联动）。

## 一句话摘要

RPC 客户端负载均衡 = **进程内选实例**（无 LB 设备的网络跳转）——策略的选型按「实例是否同构 + 是否需要状态亲和 + 负载波动幅度」三问决定，策略机制深挖互指 load-balancing 系列。

**量级演进视角**：千级 QPS 的服务 RPC 配置默认够用；万级需要全链路参数调优（超时/重试/限流/序列化协议全配）；十万级必须关注序列化效率与连接池容量——治理强度随调用量级升级。

## 💡 实战提示

- 💡 默认随机/轮询起步——按需升级到加权或最少活跃
- 💡 一致性哈希的扩缩容影响（互指 LB 篇 4 的一致性哈希深度）
- 💡 决策口径：同构随机、异构加权、有状态一致性哈希、混合负载最少活跃

**Trade-off 视角**：性能与治理能力的权衡——治理面越完善框架越重，性能极致则治理面弱。团队需按实际需求对齐，不为用不到的能力买单。

## 📎 核心带走

- **核心一句话**：RPC 客户端负载均衡 = 进程内按策略从地址列表选实例——五种策略覆盖均匀/亲和/自适应三种语义
- **机制链**：地址列表 → 策略选择 → 失败重选联动上下游 → 发起调用
- **失效点/边界**：无失败重选联动上下游的策略不完整；粘性策略破坏均匀性
