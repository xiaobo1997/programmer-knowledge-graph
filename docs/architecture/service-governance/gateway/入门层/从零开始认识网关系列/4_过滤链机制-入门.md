# 网关过滤链：责任链上的治理插件

> 路由决定「去哪」，过滤链决定「怎么被治理」——认证、限流、改写、日志全部以**责任链上的过滤器**形态存在。这篇讲过滤链的编排模型、常见过滤器分类与插件化机制。

> **本文核心**：过滤链三要素——**生命周期**（pre 前置加工 / post 后置加工 / error 错误处理）、**排序**（Ordered 值决定执行次序，跨全局与路由级统一排序）、**作用域**（全局过滤器 vs 路由级过滤器）。**机制链**：请求 → 前置链按序执行（任一中断即短路返回）→ 转发 → 后置链逆序加工 → 异常进错误过滤器。**插件化**：过滤器即插件（标准接口 + 动态加载/配置启停），网关的扩展性就是过滤器生态的丰富度。

## 一句话摘要

责任链的两个关键语义：**短路**（前置链中认证过滤器拒绝请求 → 直接返回 401，后续链不再执行——安全与性能的双重语义）与**逆序**（后置链按前置的逆序执行——先进的	后出，日志计时过滤器「前置记时间、后置算耗时」依赖逆序配对）。常见过滤器分类：**安全类**（认证/鉴权/防重放）、**流量类**（限流/熔断）、**加工类**（改写/加头/脱敏）、**观测类**（日志/链路/指标）——四类过滤器的编排顺序有行业惯例（安全 → 流量 → 加工 → 观测贯穿）。

## 一、为什么责任链是网关的骨架

横切治理的本质是「多个治理动作按序作用于同一请求」——责任链模式（每个过滤器处理完交给下一个）正是这个形态的模式化表达。责任链的三个工程红利：**可编排**（顺序可配，治理流程可重排）、**可插拔**（过滤器启停不影响彼此）、**可扩展**（自定义过滤器实现接口即可入链）——网关的「治理平台化」就建立在过滤链的这三个红利上。

## 三、与 Sentinel 过滤器/中间件链的区别：层次对照

| 维度 | 网关过滤链 | 应用内中间件链/SDK Filter（互指 stability/rpc） |
|---|---|---|
| 位置 | 入口层（南北向） | 进程内（服务自身） |
| 治理对象 | 全站入口流量 | 单服务的进出请求 |
| 关系 | 网关限流是入口闸门 | 进程内限流是最后防线 |

同一套「过滤器/拦截器」模式在多层复用——**模式同构、位置不同、职责不同**；全链路的过滤策略要在各层间分工（入口挡粗、进程内守细）——粗细分工是延迟成本与治理粒度之间的权衡，跨层演进的方向是治理语义统一、执行位置按需。

## 四、典型场景与误区

**典型场景**：统一认证过滤器（JWT 校验 + 用户上下文注入，后端免鉴权重复建设）、灰度标记注入过滤器（入口染色，互指 service-routing 篇 5）、响应脱敏过滤器（后置统一处理身份证/手机号脱敏）、防重放过滤器（时间戳 + nonce 校验）。

**误区与不适用**：① 过滤器里调远程服务——前置链串行调用远程（如认证查库）会线性放大入口延迟，认证信息本地化/缓存化是规范；② 观测过滤器放链尾——日志过滤器应最前置（记录原始请求）与最后置（记录最终响应），贯穿而非单点；③ error 过滤器只返回 500——错误过滤器要区分异常类型（认证异常 401 / 限流 429 / 上游异常 502），统一 500 是排查噩梦。

## 五、💡 实战提示

- 💡 链上耗时分位值监控到过滤器粒度——链变慢时精确到「哪个过滤器」
- 💡 过滤器启停进配置中心：异常过滤器可热下线（互指 config-center 篇 4）
- 💡 自定义过滤器按「观察模式」惯例上线（只记录不生效 → 灰度 → 全量）
- 💡 作用域选型决策口径：何时用什么——认证日志等横切全局级、特定路由定制路由级、试探性逻辑一律观察模式

## 六、你们可能会问

**Q1：前置链短路的响应也走后置链吗？**
短路返回通常不走完整后置链（请求未达上游）——但观测类需求（记录被拒绝的请求）要设计「短路也记录」的机制（error 过滤器或短路前的观测埋点），语义按网关实现确认。

**Q2：过滤器之间怎么传递数据？**
链上上下文对象（Exchange/Context）——前置换入、后置读取（认证过滤器放入用户信息，后置脱敏读取）——上下文的键规范是协作契约，乱放键等于无契约。

**Q3：过滤器和网关插件什么关系？**
插件 = 过滤器 + 管理面（启停/配置/版本）——过滤器是机制，插件是产品化包装；APISIX/Kong 的插件生态就是把过滤器模式产品化的代表。

- **核心一句话**：过滤链 = pre/post/error 三生命周期 + 全局统一排序 + 可插拔过滤器，网关治理的编排骨架
