# 版本化与演进

> URL vs 头版本 / 兼容性原则 / 废弃流程——API 的长期契约管理。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 版本策略三选一

- URL 版本：/v1/users——直观、易路由、缓存友好（最常用）
- 头版本：Accept: application/vnd.xx.v2+json——URL 稳定但可读性差
- 无版本 + 兼容演进：加字段不删字段——理想态，要求严格的变更纪律

## 兼容性判断原则

- 兼容：加可选字段/加新接口/加枚举值（消费端容忍未知字段）
- 不兼容：删字段/改字段语义/改字段类型/必填变更
- 原则：消费端「容忍未知」是 API 生态的公共道德（Postel 法则）

## 废弃流程

- 标记：响应头 Deprecation/Sunset + 文档标注
- 过渡期：新旧并行 + 流量监控 + 通知迁移（按消费方清单催迁）
- 下线：410 Gone + 迁移完成报告——没有监控的废弃 = 永远下不了线
