# REST 是什么：风格与约束

> Fielding 六约束——「像 Web 一样设计 API」到底指什么。REST 是风格不是协议。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## REST 的出身与定位

- Fielding 2000 博士论文第五章：Web 为什么能扩展到今天这个规模——总结出的架构约束集
- REST 是架构风格（约束集合），HTTP 是协议——REST 说的是怎么用好 HTTP
- 与其他 API 风格的关系：RPC（动作思维）/GraphQL（查询思维）/gRPC（二进制契约）——选型视角点出不展开

## 六个架构约束

- 资源 + 统一接口：操作对象是资源，接口统一为 HTTP 方法语义
- 无状态：每个请求自包含，服务端不存会话（水平扩展的前提）
- 缓存：响应自声明可缓存性（Cache-Control）
- 分层系统 / 按需代码（可选）：客户端无需感知中间层

## 约束的工程价值

- 无状态 → 水平扩展（回指分布式系统设计高扩展篇）
- 统一接口 → 中间层（网关/缓存/代理）可理解流量
- 缓存 → 性能（回指缓存架构篇）——约束不是教条是收益
