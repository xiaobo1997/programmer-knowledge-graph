# ⬡ REST 设计

> 跨语言 API 风格设计：资源思维、HTTP 语义、幂等安全、版本化与错误设计。REST 是「把 HTTP 的既有语义用对」，不是协议。

## ⚡ 速查卡

| 机制 | 一句话结论（为什么） | 哪里会坏 | 篇目 |
|---|---|---|---|
| 六约束 | 每条约束防一个 Web 规模敌人（无状态抗扩容/统一接口抗演进） | 无状态被 session 破坏；0 级 API 自称 RESTful | [篇1](./入门层/从零开始认识REST设计系列/1_REST是什么-风格与约束-入门.md) |
| HTTP 语义 | 方法属性+状态码是给网关/CDN/重试组件的契约 | 全 POST+200 让生态全部失明 | [篇2](./入门层/从零开始认识REST设计系列/2_HTTP语义用对-入门.md) |

| 错误与契约 | RFC 9457 结构化 + OpenAPI 单一事实源 | 文档过期；错误堆栈外泄 | [篇6](./入门层/从零开始认识REST设计系列/6_错误设计与OpenAPI规范-入门.md) |

> 金句：REST 约束管「演进」，HTTP 语义管「协作」，OpenAPI 管「契约」——三者合一方能对齐 Web 生态的免费红利。
