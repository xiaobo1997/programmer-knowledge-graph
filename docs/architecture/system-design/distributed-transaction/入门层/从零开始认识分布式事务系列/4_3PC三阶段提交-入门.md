# 3PC 三阶段提交

> 引入 CanCommit 与超时的改进——缓解阻塞但未根治。对标 DDIA。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 三阶段流程

- CanCommit：只询问不锁资源（轻量探测）
- PreCommit：全部 yes 后预提交（锁资源写日志）
- DoCommit：最终提交；参与者有超时兜底（超时未收到 DoCommit 自行提交）

## 3PC 改进了什么

- CanCommit 轻探测：减少无效锁定（早期发现 no 就不锁）
- 参与者超时兜底：协调者失联时默认提交（不再无限卡死）

## 为什么 3PC 仍不流行

- 超时默认提交在分区下会数据不一致（两边各自决定）
- 多一轮往返性能更差
- 网络分区下的根本两难没解决（引出柔性事务的思路转换）
