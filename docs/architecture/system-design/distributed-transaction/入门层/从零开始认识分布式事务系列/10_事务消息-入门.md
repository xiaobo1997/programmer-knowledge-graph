# 事务消息

> Half 消息 / 回查——MQ 侧的可靠消息方案（机制视角，实现细节回指 RocketMQ 专题层）。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 半消息机制

- 发送 Half 消息（对消费者不可见）→ 执行本地事务 → Commit（可见）/Rollback（删除）
- 本质：把「本地事务与发消息的原子性」拆成两步 + 一个待定状态
- 相比本地消息表：消息状态由 MQ 管理，业务库不建表

## 事务回查

- 本地事务执行后应用挂了 → Half 消息悬而未决
- MQ 定时回查生产者：查本地事务到底成没成（要提供查询接口）
- 回查设计的坑：查询要幂等、要容忍多次回查、查不到的默认策略

## 机制视角的边界

- 本篇只讲「事务消息作为最终一致手段」的机制
- RocketMQ 组件实现（Half 流程源码/回查配置）回指 middleware/rocketmq 事务消息深度专题
- Kafka 无原生事务消息（有幂等生产者+事务 API 但语义不同），选型时注意
