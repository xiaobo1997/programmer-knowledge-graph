# 分布式事务选型决策

> 一致性 vs 性能 vs 侵入度的决策树——把三极谱系变成选型动作。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 选型的三个问题

- 不一致的业务代价多大（资金/库存/积分/通知排序）？
- 可接受的不一致窗口多长（实时/秒/分钟/天）？
- 团队能承受的实现复杂度与基建依赖（TCC 改造量/Seata 运维/MQ 能力）？

## 决策树

- 强一致刚需（资金记账级）且并发低 → XA（数据库原生）
- 强一致但高并发热点 → 重新审视业务：多数「强一致」其实是柔性够用
- 短事务 + 资源预留可行 → TCC（性能最好，改造量最大）
- 长流程 → Saga（状态机编排）
- 可接受秒级延迟 → 本地消息表 / 事务消息（最常用）
- 以上都不是 → AT（低侵入快速落地，注意全局锁）

## 组合使用与反模式

- 同一链路可组合：核心 TCC + 外围消息最终一致
- 反模式：全链路上强一致（性能崩溃）/ 全靠对账不管实时（体验崩溃）
- 选型文档化：记录代价定价与窗口承诺，评审有据可查
