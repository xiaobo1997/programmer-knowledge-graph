# Saga 长事务

> 正向服务 + 补偿服务——长流程跨服务的柔性方案，编排式 vs 协同式。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## Saga 的适用场景

- 长流程：跨多服务的业务链（下单→扣库存→扣款→物流），TCC 长期锁资源不现实
- 核心思想：把长事务拆成 T1..Tn 本地事务 + 补偿 C1..Cn-1
- Ti 失败 → 逆序执行 Ci 补偿（撤机票、退扣款）

## 两种协调方式

- 编排式（Choreography）：服务间发事件互相触发——解耦但流程分散难追踪
- 协调式（Orchestration）：中央协调器驱动流程（状态机）——流程清晰，协调器是关键组件
- 复杂流程选协调式（Seata Saga 状态机引擎）

## Saga 的约束与坑

- 无隔离性：中间状态对外可见（预留语义要自己设计，类似 TCC 的 Try）
- 补偿必须幂等 + 可空跑（补偿先于正向到达）
- 补偿失败不能放弃：重试 + 人工干预兜底（对账体系衔接）
