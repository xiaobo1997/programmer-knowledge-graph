# 分布式事务是什么与为什么难

> 本地 ACID 失效 → 分布式挑战——「begin; commit;」跨了两个库就不再可靠。对标深入理解分布式事务。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 单机到分布式，失去了什么

- 单库 ACID：原子性/一致性/隔离性/持久性由数据库保证
- Spring @Transactional 的舒适区：一个连接一个事务，回滚即安全
- 旧世界的隐含前提：同一个 DB 实例说了算

## 跨库之后发生了什么

- 订单库扣了、库存库没扣：两个本地事务之间没有「共同的裁判」
- 网络不可靠：提交请求可能丢失/迟到（回指分布式理论两大公理）
- 锁不住远方：本地锁无法协调另一个库的事务（引出 2PC 集中协调）

## 分布式事务的问题域

- 原子性：多个节点的操作要么全成功要么全失败
- 隔离性：全局锁 vs 性能的两难
- 一致性的分级：强一致 / 柔性 / 最终一致（引出三极谱系）
