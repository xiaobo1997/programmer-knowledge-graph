# AT 自动补偿模式

> Seata AT——undo log 自动生成回滚的全局事务，全局锁机制拆解。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## AT 的「无侵入」从哪来

- 业务只写本地事务 SQL，框架代理数据源自动干三件事：解析 SQL、记前后镜像、生成 undo log
- 一阶段：本地事务内写业务数据 + undo log（同库同事务，无分布式锁）
- 二阶段：全局提交 → 异步删 undo log；回滚 → 按 undo log 反向补偿

## 全局锁与隔离性

- 全局锁：同一行在同一全局事务期间被锁，防脏写（两个全局事务改同一行）
- 全局锁是 AT 性能的关键约束：热点行会成为瓶颈
- 隔离级别默认读未提交（全局视角），需要的场景要 @GlobalLock 或换 XA

## AT 的坑与适用边界

- undo log 反解析只能回滚 DML 效果，不解决业务语义（无 TCC 的预留语义）
- 脏写检查：afterImage 与当前数据不符则回滚失败转人工
- 适用：中等并发 + 关系型库 + 想低侵入；高并发热点行场景慎重
