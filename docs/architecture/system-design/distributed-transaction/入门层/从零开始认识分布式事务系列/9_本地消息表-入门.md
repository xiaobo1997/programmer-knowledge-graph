# 本地消息表

> 消息表 + 轮询——最朴素的可靠消息方案，业务与消息同库同事务。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 核心思想：业务与消息绑一个事务

- 业务操作 + 插入消息记录在同一个本地事务（原子性由单库保证）
- 后台任务轮询消息表投递 MQ；投递成功标记完成
- 消息不丢的保证：消息记录和业务数据同生共死

## 四个工程细节

- 消息状态机：待投递/投递中/已投递/已失败（可重试次数上限）
- 投递幂等：下游按消息 ID 去重（回指分布式理论幂等篇）
- 扫表效率：索引 + 分片 + 批量；量大后扫表成瓶颈
- 顺序性：同业务键的消息要有序（分区路由）

## 与事务消息的对比

- 本地消息表：自己建表自己扫，依赖 DB，实现简单可控
- 事务消息：MQ 承担半消息与回查（篇 10），少建表但依赖 MQ 能力
- 两者都是「最终一致」极的实现，选型看团队基建（回指篇 12）
