# 2PC 两阶段提交

> 准备 / 提交两阶段——强一致的经典解与阻塞代价。对标 DDIA。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 两阶段流程

- 阶段一 Prepare：协调者询问所有参与者能否提交，参与者锁资源、写日志、应答 yes/no
- 阶段二 Commit：全部 yes → 各自提交；任一 no → 全部回滚
- 本质：把「单库 commit」扩展成「多数库共同 commit」

## 2PC 的问题

- 同步阻塞：Prepare 后参与者持锁等待，协调者挂了全体卡死（协调者单点）
- 网络分区的两难：参与者收不到 Commit 请求，锁资源还是释放
- 性能：两轮网络往返 + 锁持有时间长，吞吐低

## 2PC 的定位

- 数据库/XA 事务的内核机制（篇 5）
- 跨库强一致的理论底座，但生产直接用得少（阻塞代价）
- 理解 2PC 是理解所有协调型协议的地基
