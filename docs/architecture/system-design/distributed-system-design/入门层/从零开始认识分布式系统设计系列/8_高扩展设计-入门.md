# 高扩展设计

> 水平扩展 / 无状态 / 分片 / 服务化——随业务增长的系统能力。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 扩展性 vs 弹性 vs 灵活性

- Scalability 扩展性：加资源就能加处理能力（本篇主角）
- Elasticity 弹性：自动按负载伸缩（K8s HPA 时代的能力）
-  Agility 灵活性：业务变更的系统适应速度（微服务动机）

## 无状态是水平扩展的前提

- 会话数据外移：session → Redis / JWT 无状态令牌
- 本地缓存与无状态的矛盾：本地缓存数据不一致，慎用于强一致数据
- 无状态后扩容 = 加机器 + 负载均衡生效

## 数据层的扩展：分片

- 应用无状态后，数据成为扩展瓶颈 → 分库分表（归 MySQL 系列深挖）
- 分片键选择决定扩展边界与跨片查询代价
- 服务化的扩展：业务维度拆分（回指架构演进篇 2）
