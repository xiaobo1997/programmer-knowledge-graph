# 异步削峰

> MQ 削峰填谷 / 异步解耦 / 消息堆积应对——把瞬时洪峰摊平成平稳消费。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 削峰填谷的本质

- 瞬时流量（秒杀/账单日）超过系统处理能力 → 队列缓冲 + 按能力消费
- 用户侧体验：快速受理（入队成功）+ 异步完成（结果稍后可查）
- 代价：延迟可见、需要处理失败重试与幂等

## 异步解耦

- 同步链路：A 调 B 调 C，任一慢全链路慢
- 异步：主链路只做核心动作，副动作（通知/积分/日志）发消息
- 解耦后各服务独立扩容、独立故障（回指稳定性工程）

## 消息堆积与消费速率

- 堆积根因：消费能力不足 / 消费逻辑慢 / 下游故障
- 应对：扩消费者（注意队列数上限）、临时转储、降级非核心消费
- 堆积是「设计的债」：监控消费延迟（lag）作为核心指标（回指稳定性工程）
