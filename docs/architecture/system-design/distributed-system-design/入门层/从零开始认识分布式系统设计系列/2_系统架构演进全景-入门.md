# 系统架构演进全景

> 单体 → 垂直拆分 → 分布式 → 微服务——每一步解决什么、引入什么。对标大型网站技术架构的演进思想。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 演进线四阶段

- 单体：部署简单、事务容易；规模大后长成一坨（发布风险/团队冲突）
- 垂直拆分：按业务切应用 + 数据库；解决应用耦合，仍有重复代码
- 分布式/服务化：RPC 拆服务 + 中间件（缓存/MQ/分库分表）；引出分布式问题
- 微服务：细粒度 + 独立部署 + DevOps；运维复杂度指数上升

## 演进的驱动力与代价

- 每一步 = 解决上一阶段问题 + 引入新问题
- 业务量/团队规模是演进依据，不是「技术新潮度」
- 过早微服务 = 为想象中的问题付真实的复杂度代价

## 读演进线的正确姿势

- 判断自己业务处于哪一阶段、下一阶段的触发条件是什么
- 架构回退也是演进（合并过碎的服务）
- 演进是持续过程不是终点
