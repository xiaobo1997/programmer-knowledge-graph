# 号段模式进阶

> Leaf segment 深度 · DB 压力与段大小权衡 · 缓存与号段结合 · 跳号率治理

## 系列定位

入门层「号段模式」讲了双 buffer 消毛刺的基本原理，本专题深入生产环境的棘手问题：
号段不是「越大越好」——段大小直接决定 DB 压力、跳号率、扩容成本。

## ⚡ 速查卡

| 机制 | 一句话结论（为什么这样设计） | 哪里会坏 | 篇目 |
|---|---|---|---|
| Leaf Segment | 双 buffer：内存段耗尽才拉 DB，毛刺归零 | 拉段并发冲突=重复段 | 篇1 |
| 段大小权衡 | 三档：10w（小）/100w（中）/1000w（大），越大 DB 越轻但跳号越多 | 固定段大小不随量级调 = 浪费或不够 | 篇2 |

| 跳号治理 | 跳号不可怕，可怕的是不知道跳了多少 | 对账缺失=业务层发现不了 | 篇4 |
