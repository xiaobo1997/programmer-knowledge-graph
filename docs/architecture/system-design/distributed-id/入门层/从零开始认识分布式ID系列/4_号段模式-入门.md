# 号段模式

> DB 批量发号 + 内存分配 + 双 buffer——号段思想与 Leaf segment。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 号段的核心思想

- 一次从 DB 取一段号（如 1-1000）放内存，业务来取直接内存分配
- DB 压力从「每次发号」降为「每次号段用尽」（1/1000）
- DB 只存「当前最大值」，行锁竞争极小

## 双 buffer 优化

- 单 buffer 问题：号段用尽瞬间同步取号段，抖动尖刺
- 双 buffer：当前号段用到 10% 时异步预加载下一个
- Leaf segment 即此方案：美团技术博客为权威源（6768 stars，已停更——思想可借鉴、落地多自研）

## 号段模式的边界

- 严格递增但单实例内：多实例并发时趋势递增非严格
- 跳号：重启/宕机会浪费未用完的号段（订单号无妨，连续流水不行）
- DB 高可用是生命线：DB 挂了发号停（主从延迟窗口内用旧号段有重复风险，需读主或双 DB）
