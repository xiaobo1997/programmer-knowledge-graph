# 分布式 ID 是什么与为什么需要

> 单机自增失效 → 全局唯一 + 趋势递增 + 信息安全三个诉求的由来。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 单机自增失效的场景

- 分库分表后：两个库各自 AUTO_INCREMENT，全局必然重复
- 多活/多机房写入：各自的号段互不知晓
- 替代性标识需求：订单号/流水号/消息 ID/traceId 都要全局唯一

## 三个核心诉求

- 唯一性：全局不重复（硬性底线）
- 有序性：趋势递增保护 InnoDB 聚簇索引（顺序写 vs 页分裂）
- 信息安全：连续 ID 暴露业务量（今天比昨天多 3 万单）

## 诉求决定方案

- 只要唯一 → UUID 即可（traceId/幂等键）
- 要有序 + 高性能 → 雪花系
- 要严格递增 → 号段系
- 对外可见 → 加脱敏/加密（第 8 篇）
