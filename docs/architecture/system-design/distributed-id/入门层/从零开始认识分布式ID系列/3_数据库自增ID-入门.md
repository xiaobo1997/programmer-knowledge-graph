# 数据库自增 ID

> 单库自增的舒适区与多库步长方案的极限。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 单库自增的本质

- AUTO_INCREMENT：库内全局锁保障连续分配
- 优点：严格递增、实现零成本、有业务语义（第 1 条订单）
- 前提：只有一个写入点

## 多库步长方案

- 分 N 库各设起始偏移 + 步长 N（库 1 发 1,4,7…，库 2 发 2,5,8…）
- 优点：简单可用一时；缺点：扩容要停机重设步长（历史包袱）
- 号段模式的前身：步长 = 1 的特例

## 为什么走不远

- DB 单点写入瓶颈：发号吞吐受限于单库写入
- 扩容困难：步长方案扩容是灾难（号段冲突）
- 结论：小规模可用，正式分库直接上号段/雪花
