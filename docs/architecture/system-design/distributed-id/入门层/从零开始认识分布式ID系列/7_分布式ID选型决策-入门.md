# 分布式 ID 选型决策

> 唯一性 / 有序性 / 性能 / 长度 / 信息泄露五维决策树。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 决策树

- 内部主键（不外露）：雪花系（性能 + 趋势递增 + 短）
- 要严格递增：号段系（接受 DB 依赖与跳号）
- 对外业务单号：规则化设计（第 8 篇）+ 加密/脱敏
- 只要唯一不要有序：UUID / Redis（traceId/幂等键）

## 五个维度的检查清单

- 唯一性：重复的代价是什么（资金 ID 重复 = 事故）
- 有序性：InnoDB 主键？排序展示？
- 性能：单机 QPS 需求 vs 发号能力；外部依赖故障时的降级
- 长度与存储：bigint 16 字节 vs UUID 36 字符（索引差异）
- 信息泄露：ID 可推断业务量？对外需脱敏？

## 常见错配

- 对外订单号直接用雪花（暴露业务量 + 可枚举）
- 高并发场景用号段单点（DB 打挂）
- 把 UUID 当 InnoDB 主键（页分裂性能灾难）
