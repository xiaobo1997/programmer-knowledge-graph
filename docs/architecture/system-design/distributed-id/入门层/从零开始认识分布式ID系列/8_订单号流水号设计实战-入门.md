# 订单号流水号设计实战

> 金融订单号 / 流水号的规则设计 + 脱敏——收束全系列到生产落地。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 订单号的业务需求

- 全局唯一 + 趋势递增（索引友好）+ 可读性（客服能念、能对账）+ 不可推断业务量
- 规则化设计示例：业务前缀(2) + 日期(8) + 雪花/号段序列(12) + 校验位(2)
- 校验位防误输（类似银行卡 Luhn 算法）

## 信息脱敏设计

- 纯雪花订单号的问题：时间戳可反推、连续性暴露量级
- 脱敏手段：雪花位打散 / 加密存储对外映射 / 混淆段（随机盐）
- 对账与排查的平衡：完全无规律的对账成本高，规则化是折中

## 流水号的特殊要求

- 金融流水：与账务日切联动（日切边界归属，回指分布式事务对账篇）
- 连续性诉求：某些监管流水要求无跳号 → 号段系 + 补号机制（雪花跳号不可接受）
- 多渠道流水归一：内部统一 ID + 渠道原始流水双轨保存
