# 深入理解限流熔断参数化

> 本篇深入限流/熔断的数学模型、动态参数调优、亿级流量下的阈值计算方法。

## 一、本文核心

限流 = 令牌桶/滑动窗口控制速率
熔断 = 三态状态机保护

核心公式：桶容量 = 速率 × 突发时间，阈值 = 错误预算 / 请求量

## 二、核心机制原理穿透

### 2.1 令牌桶 (Token Bucket)

```
令牌桶模型：

    令牌生成速率: r (tokens/sec)
    桶容量: b (tokens)
    
    请求到达:
      有令牌 → 允许通过，消耗 1 令牌
      无令牌 → 拒绝/等待

关键公式：
  平均吞吐量 = r (tokens/sec)
  最大突发量 = b (tokens)
  突发持续时间 = b / r (秒)

参数调优：
  r = 目标 QPS
  b = 允许突发量 = r × 突发时间(秒)
  
  例：目标 QPS=10000，允许 2 秒突发
    r = 10000 tokens/sec
    b = 10000 × 2 = 20000 tokens
```

### 2.2 滑动窗口 (Sliding Window)

```
滑动窗口模型：

    窗口大小: w (seconds)
    阈值: t (requests/window)
    
    请求到达:
      窗口内请求 < t → 允许
      窗口内请求 ≥ t → 拒绝

关键公式：
  平均吞吐量 = t / w (requests/sec)
  最大突发 = t (整个窗口一次性请求)

参数调优：
  w = 1s (精确控制) 或 10s (平滑控制)
  t = 目标 QPS × w
  
  例：目标 QPS=10000，窗口 1s
    w = 1s
    t = 10000 × 1 = 10000 requests
```

### 2.3 漏桶 (Leaky Bucket)

```
漏桶模型：

    漏出速率: r (requests/sec)
    桶容量: b (requests)
    
    请求到达：放入桶中
    漏出：恒定速率 r 处理

关键公式：
  平均吞吐量 = r (恒定)
  最大排队 = b (requests)
  最大延迟 = b / r (秒)

特点：强制平滑输出，不适用突发场景
```

## 三、关键参数与边界条件

### 3.1 熔断器参数

| 参数 | 含义 | 默认值 | 调优建议 |
|---|---|---|---|
| **errorRateThreshold** | 错误率阈值 | 50% | 亿级 30-40% |
| **callVolumeThreshold** | 最小请求数 | 20 | 亿级 100-1000 |
| **statisticalWindowMs** | 统计窗口 | 10000ms | 亿级 5000ms |
| **slowRateThreshold** | 慢调用比例 | 0 | 亿级 10% |
| **slowDurationThreshold** | 慢调用阈值 | 0ms | 100-500ms |
| **waitDurationInOpenState** | Open 超时 | 5000ms | 亿级 1000-3000ms |
| **permittedNumberOfCallsInHalfOpenState** | Half-Open 允许请求数 | 10 | 亿级 50-100 |

### 3.2 熔断阈值计算

```
熔断阈值 = f(错误预算, 请求量, 响应时间)

错误预算公式：
  错误预算 = SLO × (1 - 可用性目标)
  
  例：SLO = 10000 QPS, 可用性 99.9%
    错误预算 = 10000 × 0.1% = 10 QPS
    
熔断阈值 = 错误预算 / 统计窗口内请求量
  = 10 / (10000 × 5s) = 0.0002 = 0.02%
  
  → 错误率超过 0.02% 触发熔断
```

## 四、生产事故与排查

### 事故 1：熔断误触发

**场景**：某系统熔断器频繁误触发，正常请求被拒绝。

**现象**：
- 熔断器频繁 Open/Close
- 正常请求被拒绝
- 用户体验下降

**根因**：
- `callVolumeThreshold` 设置过低
- 少量请求失败即触发熔断
- 统计窗口太短，波动大

**修复**：
1. 增大 `callVolumeThreshold` 到 100+
2. 增大 `statisticalWindowMs` 到 5-10s
3. 设置 `slowRateThreshold` 监控慢调用

### 事故 2：限流阈值不合理

**场景**：某系统限流阈值固定，大促期间流量暴增。

**现象**：
- 大促流量是日常 10 倍
- 限流阈值未调整
- 大量请求被拒绝

**根因**：
- 限流阈值固定，不随流量变化
- 未配置动态限流

**修复**：
1. 动态限流：根据当前流量自动调整
2. 大促前预热：临时提高阈值
3. 分级限流：核心接口低阈值，非核心高阈值

## 五、业内惯例

- 令牌桶适合突发场景，滑动窗口适合精确控制
- 熔断器三态：CLOSED → OPEN → HALF_OPEN
- 错误预算 = SLO × (1 - 可用性目标)
- 动态限流：PID 控制器反馈调整

## 六、核心带走

- **核心一句话**：限流 = 令牌桶/滑动窗口控制速率，熔断 = 三态状态机保护
- **参数公式**：桶容量 = 速率 × 突发时间，阈值 = 错误预算 / 请求量
- **亿级调优**：阈值降低 50%、窗口缩短 10 倍、Open 超时缩短 5 倍
- **哪里会坏**：阈值过低误触发、窗口太短波动大、固定阈值不适应流量变化
