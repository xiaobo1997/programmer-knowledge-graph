# 亿级高可用选型决策

> 本篇是高可用体系的专题层收束篇，提供亿级下的单元化/多活/异地灾备选型决策树与 Trade-off 评估。

## 一、本文核心

亿级高可用 = 事前四道防线 + 事中 1-5-10 + 事后复盘

核心指标：告警延迟 < 30s、On-Call < 3min、止血 < 10min

## 二、核心机制原理穿透

### 2.1 事前四道防线量化

```
事前四道防线（量化指标）：

  ┌──────────────────────────────────────┐
  │ ① 变更防线                            │
  │    灰度比例：1% → 10% → 50% → 100%    │
  │    自动回滚：错误率 > 0.1% → 回滚      │
  │    回滚时间：< 5min                    │
  ├──────────────────────────────────────┤
  │ ② 流量防线                            │
  │    限流阈值：= 单机容量 × 0.8        │
  │    熔断阈值：= 错误预算 / 请求量       │
  │    降级开关：一键降级                    │
  ├──────────────────────────────────────┤
  │ ③ 预案防线                            │
  │    预案覆盖：100% 核心场景              │
  │    演练频率：每月 1 次                  │
  │    演练通过率：> 90%                   │
  ├──────────────────────────────────────┤
  │ ④ 资损防线                            │
  │    对账频率：实时 + 分钟级 + 日级       │
  │    补偿时效：< 1h                       │
  │    追回率：> 99%                      │
  └──────────────────────────────────────┘
```

### 2.2 事中 1-5-10 量化

```
事中 1-5-10（亿级量级调整）：

  1 分钟发现：
    → 告警覆盖度：100% 核心指标
    → 告警延迟：< 30s
    → 告警准确率：> 95%
    
  5 分钟响应：
    → On-Call 到位：< 3min
    → 值班表：覆盖所有核心链路
    → 升级链：P0 → P1 → P2
    
  10 分钟止血：
    → 一键回滚：< 5min
    → 降级开关：< 3min
    → 限流调整：< 2min
```

## 三、关键参数与边界条件

### 3.1 成熟度模型 L0-L4

| 级别 | 特征 | 关键动作 | 指标 |
|---|---|---|---|
| **L0 救火式** | 故障靠用户发现 | 定核心 SLI + 两级告警 | MTTR > 1h |
| **L1 有工具** | 核心指标有告警 | 定 SLO + 错误预算 | MTTR ~ 30min |
| **L2 有流程** | 有预案 + 演练 | 预案落文档 + 定期演练 | MTTR ~ 15min |
| **L3 有体系** | 全链路监控 + 混沌工程 | 全链路追踪 + 混沌工程 | MTTR ~ 5min |
| **L4 自适应** | 自愈 + 智能运维 | AI 自动修复 + 弹性伸缩 | MTTR < 1min |

### 3.2 单元化/多活/灾备选型

**单元化**：
```
单元化架构：

  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ 单元 1    │    │ 单元 2    │    │ 单元 3    │
  │ (用户A-M)│    │ (用户N-Z)│    │ (备用)    │
  └──────────┘    └──────────┘    └──────────┘
       │               │               │
       └───────────────┴───────────────┘
              数据同步（异步）

  优点：
    - 故障隔离：单元内故障不影响其他单元
    - 流量隔离：单元间流量互不干扰
    - 灰度发布：单元内灰度，不影响全量
    
  缺点：
    - 数据同步延迟：单元间数据不一致
    - 跨单元查询复杂：需要跨单元聚合
    - 运维复杂：多单元管理
```

**多活**：
```
多活架构：

  ┌──────────┐    ┌──────────┐    ┌──────────┐
  │ 机房 A    │    │ 机房 B    │    │ 机房 C    │
  │ (主)      │    │ (主)      │    │ (主)      │
  │ 业务 A    │    │ 业务 B    │    │ 业务 C    │
  └──────────┘    └──────────┘    └──────────┘
       │               │               │
       └───────────────┴───────────────┘
              数据同步（双向）

  优点：
    - 机房故障不影响业务
    - 流量分散，单机房压力小
    - 用户就近访问，延迟低
    
  缺点：
    - 数据双向同步复杂
    - 数据冲突解决困难
    - 成本：三机房 = 3 倍
```

**异地灾备**：
```
异地灾备架构：

  ┌──────────┐    ┌──────────┐
  │ 主站点    │    │ 灾备站点  │
  │ (日常)    │    │ (备用)    │
  └──────────┘    └──────────┘
       │               │
       └───────┬───────┘
               │
          数据同步（异步）

  优点：
    - 主站点故障，灾备接管
    - 数据不丢失（RPO ≈ 0）
    - 成本：2 机房
    
  缺点：
    - 切换时间长：分钟级
    - 数据同步延迟：秒级
    - 灾备平时闲置
```

### 3.3 选型决策

```
选型决策树：

  数据一致性要求？
    ├─ 强一致 → CP 注册中心（Nacos/Raft/ZooKeeper）
    └─ 否 → AP 注册中心（Eureka/Consul）
    
  金融/账务场景？
    ├─ 是 → CP + 强一致协议
    └─ 否 → AP + 最终一致
    
  分区容错要求？
    ├─ 高 → AP（分区时仍可用）
    └─ 低 → CP（分区时不可写）
```

## 四、业内惯例

- 事前防线量化：变更/流量/预案/资损四道防线
- 事中 1-5-10：1 分钟发现 → 5 分钟响应 → 10 分钟止血
- 成熟度模型：L0 救火 → L1 工具 → L2 流程 → L3 体系 → L4 自适应
- 选型原则：强一致选单元化、高可用选多活、低成本选异地灾备

## 五、核心带走

- **核心一句话**：亿级高可用 = 事前四道防线 + 事中 1-5-10 + 事后复盘
- **量化指标**：告警延迟 < 30s、On-Call < 3min、止血 < 10min
- **成熟度**：L0 救火 → L1 工具 → L2 流程 → L3 体系 → L4 自适应
- **选型原则**：强一致选单元化、高可用选多活、低成本选异地灾备
- **哪里会坏**：预案不完善、演练不过关、切换流程不清晰
