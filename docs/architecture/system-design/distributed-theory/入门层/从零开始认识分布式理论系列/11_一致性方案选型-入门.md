# 一致性方案选型

> 强一致 vs 最终一致的决策树——把理论变成选型动作。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 先定业务的不一致代价

- 资金/库存超卖 → 不一致代价高 → 强一致或柔性事务
- 计数/评论/推荐 → 代价低 → 最终一致 + 读修复
- 定价公式回指分布式事务系列导读的「代价定价」

## 决策树（简化版）

- 要线性一致且能接受分区时不可用 → 共识系统（etcd/ZK 类 CP）
- 要可用性优先 → AP + 最终一致 + 因果保证（读己之写必备）
- 跨服务业务原子性 → 不是一致性模型问题，是事务问题（回指事务系列三极）

## 选型的常见错配

- 给点赞数用线性一致（浪费性能）
- 给余额只做最终一致（资金事故）
- 把「读己之写」漏掉：用户改完头像刷新看不到 → 体验 bug 的理论根源
