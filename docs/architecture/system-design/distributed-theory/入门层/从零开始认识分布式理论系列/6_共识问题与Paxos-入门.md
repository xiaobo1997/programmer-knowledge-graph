# 共识问题与 Paxos

> 共识问题的本质（多节点对同一个值达成一致）与 Paxos 的推导思路。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 共识问题的定义

- 一组节点对「一个值」达成不可撤销的一致决定（区别于事务的原子性）
- 约束：只有多数派存活就能出结果；已决定的值不可变
- 与分布式事务的边界：共识是底层组件（单值/日志），事务是业务原子性（回指事务系列）

## Paxos 的推导（从投票到多数派）

- 朴素方案失效：固定主挂了怎么办 / 全体投票挂一台就卡死
- 多数派（Quorum）交集保证：任意两个多数派必有交集，决定不可被推翻
- Basic Paxos 两阶段：Prepare（承诺不收旧提案）+ Accept（多数派接受）

## Paxos 为什么「难」与 Multi-Paxos

- Basic Paxos 只对一个值达成共识，多值需反复跑（低效）
- Multi-Paxos：选出 Leader、日志位复用多数派承诺，工程化但描述模糊
- 「难理解」催生了 Raft——引出第 7 篇的演进主线
