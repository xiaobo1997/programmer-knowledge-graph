# 一致性模型全景

> 强一致 / 顺序一致 / 因果一致 / 最终一致——多副本对外的契约谱系。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 为什么需要一致性模型

- 多副本 + 并发读写 = 同一个 key 的读取结果不确定
- 一致性模型 = 对「读取能看到什么」的契约分级
- 模型越强，实现代价越大（同步复制/共识），可用性与性能越差

## 契约谱系（从强到弱）

- 线性一致：像操作单机一样，任何读取都能看到最新已完成写入
- 顺序一致：所有节点看到相同的操作顺序（不要求与真实时间一致）
- 因果一致：有因果关系的操作全节点看到相同顺序
- 最终一致：停止写入后收敛，中间无保证

## 按场景匹配契约

- 金融余额 → 线性一致（读己之写是底线）
- 社交 timeline → 因果一致（先发帖后评论顺序不能乱）
- 点赞数/浏览量 → 最终一致（短暂偏差无业务代价）
