# BASE 理论

> 基本可用 / 软状态 / 最终一致——CAP 中 AP 路线的工程化理论。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## BASE 三个词的工程含义

- Basically Available 基本可用：故障时允许降级（响应变慢/部分功能下线/限流）
- Soft State 软状态：允许副本间存在中间状态（复制延迟）
- Eventually Consistent 最终一致：停止写入后有限时间内副本收敛

## BASE 与 CAP 的关系

- BASE 是 AP 路线的工程方法论：承认分区，放弃实时一致，换可用性与性能
- 最终一致的「有限时间」需要设计：复制延迟监控、读修复、反熵机制
- 与 ACID 对比：ACID 面向数据库事务，BASE 面向分布式服务架构

## 最终一致 ≠ 不一致

- 最终一致是严格契约：停止写入后必然收敛
- 中间态也有边界：因果一致性保证「你看到自己的写入」
- 兜底体系：幂等消费 + 对账补偿（回指分布式事务系列）
