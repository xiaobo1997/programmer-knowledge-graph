# Raft 共识算法

> 选主 / 日志复制 / 安全性三块拆解——为可理解性而设计的共识。
>
> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 设计目标：可理解性

- Raft 论文出发点：Paxos 难实现难教学，工程界需要一个「能讲清楚」的共识
- 问题分解：Leader 选举 + 日志复制 + 安全性，三块各自独立可讲
- 落地实现：etcd raft（本系列特性层深挖对象）

## Leader 选举

- 任期（Term）单调递增，Leader 心跳维持权威
- 超时随机化避免活锁；节点只投票给「日志不落后于自己」的候选人
- 多数派当选；脑裂时旧 Leader 日志较旧会被打回

## 日志复制与安全性

- 所有写经 Leader：append 日志 → 并行发 Follower → 多数派确认后 commit
- 日志匹配特性：保证各节点日志一致；冲突以 Leader 为准覆盖
- 安全性约束：提交需当前任期多数派（防止旧任期日志「还魂」提交）
