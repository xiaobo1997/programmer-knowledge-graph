# 外卡支付链路与 13 时点(深度)

> **系列第 2 篇 · 深度**
> 上一篇 [1_参与方全景与利益博弈-深度](./1_参与方全景与利益博弈-深度.md) 讲了 9 类参与方 + 3 维度框架 + 议价权 + 风险归属。本篇是**第二层 · 交易链路与时点的第一篇**——讲**外卡支付链路**——**授权/捕获/清算/结算 4 阶段 + 13 时点拆解 + 5 分钟定位 SOP + 对账默契时间窗口 + 真实事故反思**。

## 一句话定义

> **外卡支付链路 =「授权 + 捕获 + 清算 + 结算」4 阶段 +「13 个时点」拆解**。每个时点都有**「谁参与 + 耗时 + 失败影响 + 业内默认」**。一笔 100 SGD 的 VISA 卡交易，**3 秒授权 + T+3 结算**；涉及**6 个机构、2 次跨境通信、1 次换汇、3 次清算**。**业内默认：** 头部公司必须**「4 阶段全链路 + 13 时点全监控 + 5 分钟定位 SOP + 3 重保险（授权/捕获/清算）」**——**单一时点失控 = 业务亏损**。

---

## 业务背景与价值

### 为什么「外卡支付链路」是核心难题？

入门读者以为「外卡支付 = 授权 + 结算」。但外卡支付的真实复杂度在**4 阶段 + 13 时点**：

**4 阶段的真实复杂度：**
- **授权**（3 秒）：卡组织路由 + 发卡行扣款 + 授权码
- **捕获**（< 1 秒）：从冻结到清算
- **清算**（T+1 凌晨）：卡组织批量清算
- **结算**（T+3~T+7）：打款到商户

**业内默认：** 外卡支付的真实复杂度是「**4 阶段 + 13 时点 + 6 机构 + 3 重清算**」——**不是简单的「授权 + 结算」**

### 4 阶段的核心矛盾

**阶段 1：授权（秒级）**
- 矛盾：用户期望秒级响应 vs 卡组织需要 2-3 秒
- 业内默认：3DS v2 无感认证 + 风险分级

**阶段 2：捕获（秒级）**
- 矛盾：商户发货时机 vs 资金解冻时机
- 业内默认：实物商品发货时捕获，虚拟商品下单即捕获

**阶段 3：清算（天级）**
- 矛盾：批量处理 vs 实时对账
- 业内默认：T+1 凌晨批量 + 实时监控

**阶段 4：结算（天级）**
- 矛盾：多机构协同 vs 时区差异
- 业内默认：T+3~T+7 + 多机构协同

**业内默认：** 4 阶段的核心矛盾不是技术实现，是「**机构协同 + 时区差异 + 节假日 + 合规审查**」

### 监管意图：为什么「支付链路」必须可追溯？

监管对支付链路有「**资金流可追溯 + 异常及时上报**」要求：
1. **资金流可追溯**——每一笔交易必须可追溯
2. **异常及时上报**——授权失败 / 3DS 失败 / 对账不平必须上报
3. **拒付及时处理**——30 天内必须响应
4. **合规审查**——跨境收支必须申报

**专家视角：** 4 条要求**决定了外卡支付链路必须有「**资金流可追溯 + 异常上报 + 拒付处理 + 合规审查**」四重保险**——不是简单的「付款 + 收钱」

## 业务形态与模式：4 阶段详解

### 阶段 1：授权（3 秒）

**机制：**
- 用户付款 → 商户收银台
- 商户调用收单机构 API
- 收单机构创建支付订单
- 风控检查（卡号 / 金额 / 国家 / 黑名单）
- 3DS 强制决策（按风险等级）
- 卡组织路由（VISA / Mastercard / Amex / JCB / 银联国际）
- 发卡行验证（卡号 / CVV / 余额 / 风险）
- 发卡行扣款（冻结金额）
- 返回 6 位授权码

**耗时：** 2-3 秒

**失败影响：** 交易失败，提示用户换卡或换通道

**业内默认：** 授权阶段追求「**快 + 准**」——3DS v2 无感认证 + 风险分级 + 多通道切换

### 阶段 2：捕获（< 1 秒）

**机制：**
- 商户发货（实物商品）或下单（即时虚拟商品）
- 收单机构调用捕获 API
- 卡组织确认扣款（从冻结到清算）
- 发卡行正式扣款
- 不可撤销

**耗时：** < 1 秒

**失败影响：** 重新授权（如果捕获失败）

**业内默认：** 捕获阶段追求「**时机准确**」——实物商品发货时捕获，虚拟商品下单即捕获

### 阶段 3：清算（T+1 凌晨）

**机制：**
- 卡组织批量清算（所有交易）
- 下发清算文件（含交易明细 + 汇总金额）
- 收单机构接收清算文件
- 收单机构 vs 收单行对账

**耗时：** T+1 凌晨（卡组织规则决定）

**失败影响：** 第二天补发（清算文件不能修改）

**业内默认：** 清算阶段追求「**准确 + 完整**」——批量处理 + 实时监控 + 失败补发

### 阶段 4：结算（T+3~T+7）

**机制：**
- 三方对账（本方 / 卡组织 / 收单行）
- 差异处理（自动修复 + 人工工单）
- 换汇（原币 → 人民币）
- 外管申报
- 打款到商户银行账户

**耗时：** T+3~T+7

**失败影响：** 节假日延迟 + 银行延迟

**业内默认：** 结算阶段追求「**准 + 稳**」——三方对账 + 换汇 + 合规审查 + 银行打款

### 4 阶段决策矩阵

| 阶段 | 耗时 | 关键动作 | 失败影响 | 业内默认 |
|---|---|---|---|---|
| **授权** | 2-3 秒 | 卡组织路由 + 发卡行扣款 | 交易失败 | 3DS v2 + 多通道 |
| **捕获** | < 1 秒 | 从冻结到清算 | 重新授权 | 时机准确 |
| **清算** | T+1 凌晨 | 批量清算 | 第二天补发 | 实时监控 |
| **结算** | T+3~T+7 | 打款到商户 | 节假日延迟 | 三方对账 + 合规 |

**专家视角：** **4 阶段是串行**——业内默认是「**授权 2-3s + 捕获 < 1s + 清算 T+1 + 结算 T+3~T+7**」。**单一阶段失控 = 整体失败**

## 服务模型：5 分钟定位 SOP

### 异常识别（1 分钟）

**监控指标：**
- 授权成功率（< 95% 异常）
- 3DS 失败率（> 5% 异常）
- 捕获失败率（> 1% 异常）
- 对账不平率（> 0.5% 异常）
- 拒付率（> 1% 异常）

**业内默认：** 头部公司必须有**实时监控 + 异常告警 + 自动降级**

### 异常定位（2 分钟）

**5 步定位法：**
1. 监控大盘看异常指标
2. 追踪问题交易（订单号 / 卡号 / 商户号）
3. 定位异常时点（13 时点中的哪个）
4. 定位异常机构（卡组织 / 发卡行 / 收单行）
5. 定位异常原因（接口失败 / 网络超时 / 余额不足 / 3DS 失败 / 风控拦截）

### 异常处理（1 分钟）

**应急处理：**
- 自动降级（主通道失败 → 切备通道）
- 友好提示（不显示具体原因，避免钓鱼）
- 异步重试（最多 3 次，指数退避）
- 人工介入（P2 异常）

### 复盘报告（1 分钟）

**复盘内容：**
- 异常时间 + 异常指标
- 异常时点 + 异常机构
- 异常原因 + 根因分析
- 处理过程 + 处理时效
- 改进措施 + 预防措施

### 5 分钟定位决策矩阵

| 步骤 | 时长 | 关键动作 | 输出 |
|---|---|---|---|
| **异常识别** | 1 分钟 | 监控 + 告警 | 异常指标 |
| **异常定位** | 2 分钟 | 5 步定位 | 异常时点 + 机构 |
| **异常处理** | 1 分钟 | 降级 + 重试 | 处理结果 |
| **复盘报告** | 1 分钟 | 根因 + 改进 | 复盘报告 |

**业内默认：** **5 分钟定位是头部公司的核心能力**——监控 + 告警 + 定位 + 处理 + 复盘 5 步齐全

## 核心功能用例

### 用例 1：新加坡 VISA 付 100 SGD

**场景：** 新加坡持卡人（DBS VISA）买深圳 SaaS 公司订阅（100 SGD）

**4 阶段 13 时点全流程：**
- 阶段 1 授权：3 秒
  - 时点 1：用户下单 100 SGD
  - 时点 2：商户创建支付订单
  - 时点 3：风控检查（低风险）
  - 时点 4：3DS 决策（豁免）
  - 时点 5-6：卡组织路由 → 发卡行
  - 时点 7：DBS 验证余额 + 扣款
  - 时点 8：返回授权码 123456
  - 时点 9-11：授权成功 + 回调支付成功
- 阶段 2 捕获：< 1 秒（即时虚拟商品）
  - 时点 12-13：捕获 100 SGD
- 阶段 3 清算：T+1 凌晨
  - VISA 下发清算文件 97.6 SGD（扣手续费 2.4%）
- 阶段 4 结算：T+3
  - 三方对账
  - 换汇 97.6 SGD → 530 CNY
  - 外管申报
  - 打款 530 CNY 到商户

**时延：** 3 秒授权 + T+3 结算

### 用例 2：美国 Mastercard 付 50 USD

**场景：** 美国持卡人（Chase Mastercard）买深圳电商商品（50 USD）

**4 阶段 13 时点全流程：**
- 阶段 1 授权：5 秒（含 3DS v2 无感认证）
  - 时点 1-4：下单 + 风控 + 3DS v2
  - 时点 5-9：卡组织路由 → Chase 验证 + 扣款
  - 时点 10-11：支付成功
- 阶段 2 捕获：< 1 秒
  - 时点 12-13：捕获 50 USD
- 阶段 3 清算：T+1
  - Mastercard 下发清算文件 48.5 USD
- 阶段 4 结算：T+3
  - 换汇 48.5 USD → 350 CNY
  - 打款 350 CNY 到商户

**时延：** 5 秒授权 + T+3 结算

### 用例 3：拒付处理

**场景：** 新加坡持卡人 30 天后申诉「没买过」

**拒付全流程：**
- 持卡人申诉 → DBS（发卡行）
- DBS 发起 chargeback
- VISA 通知收单机构
- 收单机构通知商户
- 商户选择接受或抗辩

**时延：** 30-120 天

### 用例 4：对账不平处理

**场景：** T+1 凌晨清算后发现金额差异 0.01 SGD

**对账处理流程：**
- 5 分钟内告警（监控不平率 > 0.5%）
- 2 分钟定位（找差异交易）
- 1 分钟处理（自动修复或人工工单）
- 1 分钟复盘（根因 + 改进）

**时延：** 5 分钟定位 + 1-3 天处理

## 业务打法与策略：不同公司的链路管理

### 头部公司（年 GMV > 100 亿美元）

**典型做法：**
- **完整 4 阶段全链路**（端到端自动化）
- **13 时点全监控**（实时监控 + 异常告警）
- **5 分钟定位 SOP**（监控 + 告警 + 定位 + 处理 + 复盘）
- **拒付率 < 0.5%**（业内优秀）
- **结算时效 T+3**（业内最快）

**业内认知：** 头部公司是「**4 阶段全链路 + 13 时点全监控 + 5 分钟定位 + 端到端自动化**」的完整体系

### 中型公司（年 GMV 1-100 亿美元）

**典型做法：**
- **基本 4 阶段**（半自动化）
- **5-8 个时点监控**（核心时点）
- **10-30 分钟定位 SOP**（基础定位）
- **拒付率 0.5%-1%**（业内关注）
- **结算时效 T+5~T+7**（业内中等）

**业内认知：** 中型公司是「**够用但不极致**」的体系

### 小公司 / 新进入者（年 GMV < 1 亿美元）

**典型做法：**
- **基础 2 阶段**（仅授权 + 结算）
- **2-3 个时点监控**（仅异常时点）
- **人工定位**（无自动化）
- **拒付率 1%-3%**（业内警告）
- **结算时效 T+7~T+10**（业内最慢）

**业内认知：** 小公司是「**MVP 起步**」的体系

## Trade-off 分析

### 决策 1：链路管理深度

| 选项 | 优势 | 代价 | 适合谁 |
|---|---|---|---|
| **浅管理**（基础 2 阶段）| 简单 + 成本低 | 拒付率高 + 业务受限 | 小公司 |
| **中管理**（基本 4 阶段）| 平衡 + 风险可控 | 成本中等 | 中型公司 |
| **深管理**（完整 4 阶段 + 13 时点）| 风险最低 + 全球化 | 成本高 + 团队大 | 头部公司 |

**专家视角：** **链路管理深度是取舍**——业内默认是「**深管理 + 完整 4 阶段 + 13 时点全监控**」

### 决策 2：3DS 策略

| 选项 | 优势 | 代价 | 适合谁 |
|---|---|---|---|
| **不强制**（所有交易免 3DS）| 转化率最高 | 拒付率最高 | 低风险场景 |
| **按风险分级**（低风险免 + 高风险强制）| 平衡 + 风险可控 | 规则维护 | 中型公司 |
| **全量强制**（所有交易必须 3DS）| 拒付率最低 | 转化率最低 | 高风险地区 |

**专家视角：** **3DS 策略不是越多越好**——业内默认是「**按风险分级 + 3DS v2 + 强制高风险**」

### 决策 3：捕获时机

| 选项 | 优势 | 代价 | 适合谁 |
|---|---|---|---|
| **下单即捕获**（虚拟商品）| 资金即时到账 | 拒付风险高 | 数字商品 / 服务 |
| **发货时捕获**（实物商品）| 拒付风险低 | 资金到账慢 | 实物商品 |
| **预授权 + 延迟捕获**（酒店/租车）| 灵活 | 资金占用 | 酒店 / 租车 / 订金 |

**专家视角：** **捕获时机不是越早越好**——业内默认是「**实物发货时 + 虚拟下单时 + 预授权延迟**」三策略组合
