# 中间件 · 分布式任务调度

> 凡是「每天凌晨对账」「每小时跑批」「大促后结算佣金」，背后都是任务调度。单机 `@Scheduled` 写着写着就会撞上三堵墙：多实例重复执行、节点挂了任务就丢、几百个任务没人管得了。本系列从**调度机制**（触发 / 分片 / 容错）讲起，再进 xxl-job、PowerJob 的组件深挖——先懂机制，框架只是例证。

## 一、这个系列怎么读

按 4 层架构组织，每层可独立进入：

```
L1 入门层：为什么需要 + 机制心智模型 + 框架全景对比（机制是主角）
L2 特性层：组件深挖（xxl-job / PowerJob）+ 时间轮与调度算法
L3 专题层：跨特性专题（生产实战 / Quartz 迁移）
L4 整合层：全景演进 + 选型决策树 + 接入实战
```

**一句话划边界**：延迟一次执行找消息队列（RocketMQ 定时消息），周期性 / 批量 / 编排任务找任务调度——两个系列 tips 互指，不重复写。

- **backend/java（Spring Boot 系列）**：@Scheduled 单机用法在那边正式讲——本系列入门层只讲「单机局限」并互指
