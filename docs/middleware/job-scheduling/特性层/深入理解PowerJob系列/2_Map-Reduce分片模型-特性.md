# PowerJob Map-Reduce 分片模型

> PowerJob 的 Map-Reduce：把大任务拆成子任务并行执行——分片是核心。

## 一句话摘要

> Map-Reduce = 拆分（Map）+ 执行（并行）+ 合并（Reduce）——分片粒度决定性能上限。

## Map-Reduce 流程

```
大任务 → Map 拆分 → 子任务分发 → 并行执行 → Reduce 合并 → 结果汇总
```

|| 阶段 | 职责 |
|---|---|---|
| Map | 拆分大任务 | 子任务列表 |
| 分发 | 路由到 Worker | 负载均衡 |
| 执行 | 业务逻辑 | 并行 |
| Reduce | 合并结果 | 汇总 |

## 分片粒度

|| 粒度 | 适用 |
|---|---|---|
| 粗粒度 | 大任务拆少份 | 数据少 |
| 细粒度 | 大任务拆多份 | 数据多 |

## 量级参考

|| 量级 | 分片数 | Worker 数 |
|---|---|---|---|
| 10w 档 | 10-50 | 2-5 |
| 千万级 | 100-500 | 5-20 |
| 亿级 | 1000+ | 20+ |

## 生产陷阱

- ❌ 分片过细 = 开销大
- ❌ 分片过粗 = 不均匀
- ❌ Reduce 不幂等 = 结果错乱
