# xxl-job 注册发现与路由策略

> 执行器怎么找到调度中心？路由策略怎么选？这决定了系统的可用性和性能。

## 一句话摘要

> 注册发现 = 执行器上线 + 心跳保活，路由策略 = 任务派发给谁——两者共同决定任务能否到达。

## 注册发现

|| 组件 | 职责 | 失效影响 |
|---|---|---|---|
| 执行器 | 注册自身地址 | 不上线 |
| 调度中心 | 维护执行器列表 | 路由错乱 |
| 心跳 | 保活检测 | 宕机不感知 |

## 心跳机制

- 默认 10s 心跳间隔
- 超时 30s 标记离线
- 离线后任务路由到其他节点

## 路由策略详解

|| 策略 | 一句话 | 量级 |
|---|---|---|---|
| FIRST | 选第一台上线 | 最低 |
| ROUND | 轮流选 | 均匀 |
| RANDOM | 随机选 | 均匀 |
| CONSISTENT_HASH | 一致性哈希 | 分片场景 |
| LEAST_FREQUENTLY_USED | 最少使用 | 负载不均 |
| LEAST_RECENTLY_USED | 最近最少 | 冷热不均 |
| FAILOVER | 故障转移 | 高可用 |
| BUSYOVER | 繁忙转移 | 防过载 |

## 分片场景

- 一致性哈希：数据分片场景首选，扩容影响小
- 轮询：均匀场景首选
- 故障转移：高可用场景首选

## 生产陷阱

- ❌ 执行器不配心跳——宕机后任务路由到死节点
- ❌ 路由策略用默认 FIRST——单点瓶颈
- ❌ 分片场景用轮询——数据倾斜
