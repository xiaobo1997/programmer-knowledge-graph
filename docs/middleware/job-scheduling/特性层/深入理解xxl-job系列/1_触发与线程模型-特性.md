# xxl-job 触发与线程模型

> xxl-job 的核心不是「配个 cron」——触发线程池 + 执行线程池 + 回调机制，三者耦合决定性能上限。

## 一句话摘要

> xxl-job = 调度中心（触发）+ 执行器（运行）——触发线程池满 = 任务排队，执行线程池满 = 任务拒绝。

## 触发链路

```
cron 触发 → 调度中心路由 → 执行器接收 → 线程池执行 → 回调结果
```

|| 环节 | 关键参数 | 默认值 |
|---|---|---|---|
| 触发 | cron 解析 | - | 每分钟 |
| 路由 | 路由策略 | FIRST | 轮询 |
| 执行 | 线程池 | executor-thread | 50 |
| 回调 | 回调地址 | 执行器配置 | - |

## 路由策略

|| 策略 | 适用 |
|---|---|---|
| FIRST | 首机 | 开发测试 |
| ROUND | 轮询 | 均匀负载 |
| RANDOM | 随机 | 避热点 |
| CONSISTENT_HASH | 一致性哈希 | 分片场景 |
| LEAST_FREQUENTLY_USED | 最少使用 | 负载不均 |
| LEAST_RECENTLY_USED | 最近最少 | 冷热不均 |
| FAILOVER | 故障转移 | 高可用 |
| BUSYOVER | 繁忙转移 | 防过载 |

## 线程池调优

|| 场景 | 推荐线程池大小 |
|---|---|---|
| CPU 密集 | CPU 核数 + 1 | - |
| IO 密集 | CPU 核数 × 2 | - |
| 混合 | CPU 核数 × (1 + IO 占比) | - |

## 生产陷阱

- ❌ 线程池大小默认 50 不调——IO 密集场景够，CPU 密集场景爆
- ❌ 路由策略用 FIRST——单点瓶颈
- ❌ 回调失败不处理——状态不一致

## 量级参考

- 10w 档：默认线程池够用
- 千万级：调大执行线程池 + 路由优化
- 亿级：需要分片 + 多执行器集群
