# 任务调度全景与选型决策

> 从单机 cron 到云原生调度——全景演进 + 选型决策树。

## 一句话摘要

> 演进 = 单机 → 集群 → 中心化 → 云原生——选型 = 量级 + 场景 + 团队。

## 演进全景

|| 阶段 | 方案 | 量级 |
|---|---|---|---|
| 单机 | cron / @Scheduled | 万级 |
| 集群 | Quartz 集群 | 十万级 |
| 中心化 | XXL-Job | 千万级 |
| 去中心 | PowerJob | 亿级 |
| 云原生 | K8s CronJob / EventBridge | 弹性 |

## 选型决策树

```
量级？
├─ 10w → XXL-Job / Quartz
├─ 千万 → ElasticJob / XXL-Job
└─ 亿级 → PowerJob / 自研

需要秒级？
├─ 是 → PowerJob
└─ 否 → 按量级选

需要工作流？
├─ 是 → PowerJob / ElasticJob
└─ 否 → XXL-Job
```

## 取舍矩阵

|| 维度 | 中心化 | 去中心 | 云原生 |
|---|---|---|---|---|
| 简单度 | 高 | 中 | 低 |
| 可靠性 | 中 | 高 | 高 |
| 扩展性 | 低 | 高 | 高 |
| 运维成本 | 低 | 中 | 高 |

## 生产陷阱

- ❌ 不做选型直接上——后续迁移成本高
- ❌ 量级估计错——选小了撑不住
- ❌ 忽略团队熟悉度——学习成本拖累

## 量级参考

- 10w 档：单机 + 分布式锁
- 千万级：XXL-Job / ElasticJob
- 亿级：PowerJob / 自研
