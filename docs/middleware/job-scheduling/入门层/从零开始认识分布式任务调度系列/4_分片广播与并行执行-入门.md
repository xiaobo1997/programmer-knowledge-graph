# 分片广播与并行执行

> 分片不是「把任务扔给多个节点」——数据分片 vs 请求分片，策略不同、场景不同、取舍不同。

## 一句话摘要

> 分片 = 数据划分 + 路由策略 + 执行并行——核心是「怎么把 1 亿条数据均摊到 N 台机器」。

## 分片两种模型

|| 模型 | 数据流向 | 典型场景 |
|---|---|---|---|
| 数据分片 | 每台机器处理自己的那部分数据 | 对账 / 批量同步 / 数据清洗 |
| 请求分片 | 调度中心把请求路由到不同机器 | API 调用 / 远程任务 |

## 分片策略

|| 策略 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 轮询 | 简单公平 | 不考虑数据倾斜 | 数据均匀 |
| 范围分片 | 连续数据友好 | 边界难定 | 时间范围 |
| 哈希分片 | 均匀 | 扩容需 rehash | 无规律数据 |
| 一致性哈希 | 扩容影响小 | 实现复杂 | 动态扩缩 |

## 并行度控制

- 10w 档：单机并行够用
- 千万级：分片数 = 机器数 × 2~4
- 亿级：动态分片 + 背压控制

## 生产陷阱

- ❌ 分片数 > 机器数 = 热点
- ❌ 分片不均 = 长尾任务拖垮 SLA
- ❌ 分片状态不持久 = 宕机后无法恢复
