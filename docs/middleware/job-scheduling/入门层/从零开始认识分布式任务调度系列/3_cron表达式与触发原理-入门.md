# cron 表达式与触发原理

> cron 不是「写个字符串」——时区 / 解析 / 触发抖动 / 漏触发，每个都是生产事故源头。

## 一句话摘要

> cron = 时间表达式 + 触发器 + 执行上下文——三者拆开看才能理解为什么生产环境 cron 会「失灵」。

## cron 五字段

|| 字段 | 允许值 | 特殊字符 |
|---|---|---|---|
| 秒 | 0-59 | , - * / | 部分实现不支持 |
| 分 | 0-59 | , - * / | 最常用 |
| 时 | 0-23 | , - * / | 24 小时制 |
| 日 | 1-31 | , - * / ? L W | ? = 不指定 |
| 月 | 1-12 | , - * / | - |
| 周 | 1-7 | , - * / ? L # | # = 第几个星期几 |

## 生产陷阱

|| 陷阱 | 表现 | 解法 |
|---|---|---|
| 时区 | 服务器时区与 cron 时区不一致 | 统一 UTC + 显式声明 |
| 漏触发 | 月底 31 日任务在 30 月漏触发 | 用 ? 代替具体日 |
| 抖动 | 长时间任务 + cron 重叠 = 并发 | 加分布式锁 |
| 累积 | 机器宕机后任务堆积 | 漏触发补偿策略 |

## 量级影响

- 10w 档：单机 cron + Redis 锁
- 千万级：调度中心统一触发 + 分片
- 亿级：事件驱动 + 流式触发

## 常见误区

- ❌ `0 0 0 * * ?` 每天凌晨执行——没说时区，UTC vs 本地 = 错峰
- ❌ cron 字符串直接写代码——应该配置化 + 校验 + 灰度
