# 容错与补偿

> 容错不是「重试」——重试是最后一道防线，前面还有熔断、降级、补偿三道门。

## 一句话摘要

> 容错 = 故障检测 + 失败策略 + 补偿机制——三扇门，关不住就熔断。

## 故障处理链路

```
任务失败 → 立即重试(1次) → 退避重试(3次) → 告警 → 补偿 → 熔断
```

|| 策略 | 触发条件 | 动作 |
|---|---|---|---|
| 立即重试 | 临时性错误 | 重试 1 次 |
| 退避重试 | 持续失败 | 指数退避，最多 3 次 |
| 告警 | 超过阈值 | 通知运维 |
| 补偿 | 业务侧可补救 | 反向操作 / 补跑 |
| 熔断 | 连续失败 | 停止调度 + 人工介入 |

## 幂等设计

|| 维度 | 做法 |
|---|---|---|
| 任务级别 | 任务 ID + 执行时间戳去重 |
| 步骤级别 | 每步有唯一标识 + 状态机 |
| 数据级别 | 数据库唯一索引 / Redis set |

## 补偿模式

|| 模式 | 适用场景 | 复杂度 |
|---|---|---|---|
| 对账补偿 | 定时对账 + 补跑 | 中 |
| 逆向补偿 | 冲正 / 回滚 | 高 |
| 空跑补偿 | 跳过 + 记录 | 低 |

## 量级影响

- 10w 档：重试 + 告警够用
- 千万级：需要补偿 + 熔断
- 亿级：自动补偿 + 自动熔断 + 人工确认

## 常见误区

- ❌ 只重试不补偿——重试解决临时问题，补偿解决业务问题
- ❌ 熔断后不通知——熔断是保护不是消失，必须有人知道
