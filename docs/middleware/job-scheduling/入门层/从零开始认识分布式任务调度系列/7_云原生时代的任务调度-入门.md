# 云原生时代的任务调度

> K8s CronJob / Serverless / EventBridge —— 云原生不是替代，是重新定义「调度边界」。

## 一句话摘要

> 云原生调度的核心变化：调度器从「中心化进程」变成「K8s 控制器」——可靠性从应用层移到平台层。

## 三种云原生形态

|| 形态 | 调度方 | 适用 | 局限 |
|---|---|---|---|---|
| K8s CronJob | K8s Controller | 集群内定时任务 | 只能 K8s 内部 |
| Serverless 定时 | 云厂商触发器 | 无服务器场景 | 冷启动延迟 |
| EventBridge | 事件驱动 | 跨平台编排 | 复杂调度逻辑难实现 |

## 与传统调度对比

|| 维度 | 传统调度中心 | 云原生 |
|---|---|---|---|
| 部署 | 独立应用 | 控制器 + Operator |
| 扩缩 | 手动 / 脚本 | HPA / VPA |
| 可观测 | 调度中心 UI | Prometheus + Event |
| 多云 | 不支持 | 各云厂商不同 |

## 取舍主线

- 简单任务 → K8s CronJob（零额外组件）
- 复杂编排 → EventBridge + Step Functions
- 海量任务 → 传统调度平台（XXL-Job/PowerJob）

## 生产陷阱

- ❌ CronJob 超时没处理——Pod 被 kill 后状态不清理
- ❌ Serverless 冷启动影响准点触发——需要预留实例
- ❌ EventBridge 事件丢失——需要死信队列兜底
