# 日志存储与文件结构

> segment/.log/.index/.timeindex/页缓存/顺序写——「Kafka 为什么快」的存储层答案。

> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 规划大纲

### 1. 背景：消息不是即删即走

- 日志即存储的追加写模型
- 与 MySQL B+ 树存储的直觉对比

### 2. 核心：日志分段（segment）

- 活跃段与旧段 / 段内偏移连续
- .log 数据 + .index 稀疏索引 + .timeindex 时间索引

### 3. 机制：顺序写与页缓存

- 磁盘顺序写 vs 随机写的量级差
- 页缓存承担读热数据，Kafka 不自管缓存

### 4. 实践：存储相关参数

- segment.bytes / retention 与清理衔接（6 篇）
- 磁盘规划直觉（16 篇展开）
