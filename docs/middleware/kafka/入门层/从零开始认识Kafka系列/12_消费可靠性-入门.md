# 消费可靠性

> 消费语义（at-most/at-least/exactly-once）/ 幂等消费 / 重试与死信——消费端把「至少一次」变业务安全。

> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 规划大纲

### 1. 背景：三种投递语义

- broker 只保证至少一次投递
- 端到端恰好一次的组成条件

### 2. 核心：消费端幂等

- 处理幂等 vs 提交幂等
- 去重表/状态标记的落地模式

### 3. 机制：失败重试与死信

- 本地重试 vs 延迟重试
- 死信主题（DLQ）设计

### 4. 实践：消费代码模板

- 先处理后提交 / 幂等键贯穿
- 消费链路监控（Lag）
