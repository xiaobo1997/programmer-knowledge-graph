# Topic 与 Partition

> 分区数量设计 / 分区策略（key 路由）/ 分区与副本的关系——Topic 设计是 Kafka 用得好的第一课。

> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 规划大纲

### 1. 背景：Topic 是逻辑容器

- 命名规范与业务语义
- 分区数为什么定下来难改

### 2. 核心：Partition 的内部语义

- 分区的顺序保证与并行度
- 分区 = 存储单元 + 并行单元 + 副本单元

### 3. 机制：分区策略与 key 路由

- key hash / 粘性分区 / 自定义分区器
- key 的选择如何影响顺序与负载均衡

### 4. 实践：分区数设计

- 吞吐量/顺序性/扩展性三方权衡
- 分区数能改但不能任性（16 篇容量展开）
