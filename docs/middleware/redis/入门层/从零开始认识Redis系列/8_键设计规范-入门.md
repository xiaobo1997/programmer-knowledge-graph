# 键设计规范

> key 命名 / 有效期设计 / 反模式——生产事故一半出在键设计上。

> 本文为系列规划大纲页：篇目结构已定，正文按下方骨架落盘。

## 规划大纲

### 1. 背景：键是 Redis 的 Schema

- 无 schema 的自由与混乱
- 键设计影响数据分布与排查

### 2. 核心：命名规范

- 业务:模块:ID 的分层命名
- 可读性与扫描友好

### 3. 机制：有效期设计

- TTL 统一策略与兜底过期
- 热点 key 的过期打散

### 4. 实践：反模式清单

- 大 key/热 key/无过期键
- 与监控告警的配合（21 篇衔接）

### 6. 速记卡 + 下篇预告

- 一张表收束本篇关键点
- 预告下一篇的衔接问题
