- 概念多：Broker / Topic / Queue / Producer / Consumer / NameServer...

**这套系列的目标：** 让一个**没接触过 RocketMQ 的 Java 后端**，能在 1-2 周内**用上 RocketMQ 并理解原理**。

## 四、入门读者最容易踩的 3 个认知误区

### 误区 1：「RocketMQ 就是阿里版 Kafka」

❌ **错**。RocketMQ 和 Kafka 在**设计哲学、协议、特性上差异巨大**：

| 维度 | Kafka | RocketMQ |
|---|---|---|
| 设计目标 | 高吞吐日志流 | 可靠消息中间件 |
| 顺序保证 | 分区内有序 | 全局严格有序 |
| 事务 | 不支持 | 原生支持（半消息 + 回查）|
| 延迟消息 | 不支持 | 支持 18 个固定级别 |
| 消费模式 | 拉 | 推 + 拉 |
| 部署复杂度 | 高（依赖 ZK / KRaft）| 中（NameServer 轻量）|

### 误区 2：「RocketMQ 太老了，跟不上云原生」

❌ **错**。RocketMQ 5.x 已全面拥抱云原生：

- **Controller 模式**：替代 NameServer（ZK-free）
- **Proxy 模式**：存算分离，无状态 Proxy
- **Pop 消费**：低延迟消费模型
- **gRPC 协议**：跨语言客户端

### 误区 3：「会用 API 就行，不用懂原理」

❌ **错**。消息中间件出问题往往是「原理级问题」：

- 消息丢失 / 重复 → 不懂 CommitLog / 副本机制
- 消费卡死 → 不懂 ConsumeQueue / 索引原理
- 集群脑裂 → 不懂主从同步 / DLedger
- 顺序错乱 → 不懂 Queue 路由 / 消费位点

**入门阶段**至少要懂：消息发送链路 + CommitLog 写入 + ConsumeQueue 索引 + 消费者拉取这 4 段。
