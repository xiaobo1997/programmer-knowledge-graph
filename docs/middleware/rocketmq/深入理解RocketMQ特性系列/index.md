# 深入理解 RocketMQ 特性系列

> 这是 RocketMQ 学习体系的 **L2 特性层**——「一个特性 = 一篇 deep-dive」，11 篇讲透 RocketMQ 核心特性。
>
> **核心观点：** 入门层让你会用，特性层让你看穿源码、看清 trade-off，看清业内惯例与真实生产事故。

---

## 一、本系列在 4 层架构中的位置

RocketMQ 知识图谱按 `_internal/cross-model/directory-layering.md` 的标准组织为 4 层：

| 层 | 定位 | 字数 | 读者画像 | 本系列位置 |
|---|---|---|---|---|
| **L1 入门层** | 概念扫盲 + 第一步使用 | concept 5 节 | 没接触过 RocketMQ | [从零开始认识 RocketMQ 系列](../从零开始认识RocketMQ系列/0_系列导读-全景) |
| **L2 特性层** ✅ | 每个特性 1 篇深度 | deep-dive 8 节 | 会用、想深挖 | **本系列（11 篇）** |
| **L3 专题层** | 单篇讲不透的跨特性深度话题 | deep-dive × 多篇 | 想深挖某个复杂主题 | [Topic 隔离深度](../Topic隔离深度/index) / [事务消息深度](../事务消息深度/index) |
| **L4 整合层** | 跨专题综合 + 选型决策 | 全景 + 决策 | 想做技术选型 | 待建设 |

**特性层（L2）的设计原则：**

- ✅ **每个特性 1 篇 deep-dive**（5000-7000 字 · 8 节骨架 · 含源码 + trade-off + 反模式 + 业内惯例）
- ✅ **不跨特性**（跨特性 → 进 L3 专题层）
- ✅ **不重复入门层**（入门讲过的基础概念不重讲）
- ✅ **承接入门 → 导向专题**（看完能会，再深入有路可走）

## 三、学习路径建议

### 路径 A：源码级精读（推荐 / 10-15 小时）

按编号顺序 1 → 2 → ... → 11 读完，每篇配源码阅读 + 至少跑通一个 demo。

```
✅ 已写 7 篇 → 顺读 → 8 存储 → 9 集群 → 10 轨迹 → 11 收官
```

### 路径 B：问题驱动（遇到问题来查）

| 你遇到的问题 | 直读 |
|---|---|
| 消息顺序乱序 | 1 顺序消息 |
| 定时任务用 MQ 实现 | 2 延迟消息 |
| 分布式事务一致性 | 3 事务消息 |
| 发送吞吐量低 | 4 批量消息 |
| 消费者收到不需要的消息 | 5 消息过滤 |
| 消费失败处理 + DLQ | 6 消费重试与死信 |
| Broker 主挂了 | 7 主从同步 |
| 磁盘 IO 高 / 写入慢 | 8 消息存储 |
| 消费者 rebalance 抖动 | 9 集群与负载均衡 |
| 想看消息链路 | 10 消息轨迹与监控 |
| 升级 5.x / 评估云原生 | 11 收官篇 |

### 路径 C：面试突击（4 小时 / 选核心 4 篇）

- **必读**：1 顺序 + 3 事务 + 7 主从 + 11 收官
- **加分**：8 存储 + 5 过滤

### 何时**不要**读本系列

| 场景 | 替代路径 |
|---|---|
| 没接触过 RocketMQ | 先看 [L1 入门层](../从零开始认识RocketMQ系列/0_系列导读-全景) |

## 四、与同层 4 层目录的关系

### 4.1 上游：L1 入门层（前置依赖）

本系列默认你已经：
- 跑通过 RocketMQ 4.x / 5.x 的本地 demo
- 理解 Topic / Queue / Producer / Consumer / Broker / NameServer 6 大角色
- 看过至少一篇入门层文章

**缺前置 → 回入门层补。** 不会用就看 deep-dive 容易陷入「看懂原理却不会用」的窘境。

### 4.2 下游：L3 专题层（延伸路径）

| 专题层专题 | 与本系列的衔接 |
|---|---|
| [Topic 隔离深度](../Topic隔离深度/index)（7 篇 · L3 深度层） | 本系列「7 主从同步」「8 消息存储」「9 集群与负载均衡」共同构成 Topic 隔离的底层机制；想系统理解 Topic 隔离的 4 层架构与 3 个误区 → 进专题层 |
| [事务消息深度](../事务消息深度/index) | 本系列「3 事务消息原理」讲透单特性；事务消息与本地事务、幂等、补偿的工程结合 → 进专题层 |

**L2 → L3 的判定口诀（来自 directory-layering.md）：**

> 看字数：> 10000 → 拆专题；看概念：≥ 3 个核心机制 → 拆专题；看案例：≥ 5 个真实事故 → 拆专题；看演进：跨 ≥ 3 个版本 → 拆专题；都不到 → 放特性层。

### 4.3 同层横看：RocketMQ 4 层全景

```
L1 入门层（11 篇）         ← 先用起来
       ↓
L2 特性层（本系列 11 篇）   ← 每个特性看懂源码
       ↓
L3 专题层（7+7 篇）        ← 单特性讲不透的复杂主题
       ↓
L4 整合层（待建设）        ← 跨专题横向对比 + 选型决策
```

**特性层在 4 层中扮演「承上启下」的角色——它是「会」与「懂」之间的桥，也是单特性视角与跨特性视角之间的桥。**
