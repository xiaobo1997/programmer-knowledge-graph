## 核心机制（4 层架构）

```
┌─────────────────────────────────────────────────────────┐
│ Layer 4：业务隔离（Business Isolation）                  │
│ - 不同业务线用不同 Topic（订单 vs 支付 vs 通知）          │
│ - 故障域隔离（一个 Topic 慢/挂，不影响其他）             │
├─────────────────────────────────────────────────────────┤
│ Layer 3：权限隔离（Security Isolation）                  │
│ - ACL：谁能 produce/consume 哪个 Topic                  │
│ - 不同部门/租户的访问控制                                │
├─────────────────────────────────────────────────────────┤
│ Layer 2：物理隔离（Storage & Compute Isolation）        │
│ - Broker 上的存储路径隔离（CommitLog 是共享的）         │
│ - 消费位点隔离（每个消费者组独立 Offset）                │
├─────────────────────────────────────────────────────────┤
│ Layer 1：逻辑隔离（Logical Isolation）                  │
│ - Queue 是 Topic 下的子单位（Topic : Queue = 1 : N）    │
│ - 不同 Topic 的消息走不同的 Queue、不同的 ConsumeQueue   │
│ - 路由独立（NameServer 返回的 Broker 列表可不同）       │
└─────────────────────────────────────────────────────────┘
```

**关键洞察：** 真实 RocketMQ 的 Topic 隔离是**逻辑层独立、物理层共享**（CommitLog 是 Broker 级共享）。详细见专题文章。

## 3 个常见误区（速览）

### 误区 1：Topic 之间完全物理隔离
❌ 错。所有 Topic 写入**同一个 CommitLog**。

### 误区 2：不同 Topic 性能完全独立
❌ 错。共享磁盘 IO，大 Topic 写满会**拖垮其他 Topic**。

### 误区 3：Topic 隔离就是多租户隔离
❌ 错。Topic 隔离只是**消息路由隔离**，**多租户还要做资源隔离**（CPU/内存/网络）。
