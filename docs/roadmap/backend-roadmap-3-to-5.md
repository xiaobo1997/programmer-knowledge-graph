# 后端工程师技术地图：3 年到 5 年路线

> 这张图告诉你每个阶段该学什么、做到什么程度。

## 入门（0-1 年）

### 必备

- 一门主流语言（Java / Go / Python）
- 数据结构与算法基础
- SQL 与关系数据库
- HTTP/REST 基础
- Git 与 Linux 命令行

### 验收标准

- 能独立完成 CRUD 模块
- 知道常用设计模式
- 能用 SQL 写简单查询

## 进阶（1-3 年）

### 必备

- 框架原理（Spring / Gin / Django）
- 数据库调优（索引、慢查询、事务隔离）
- 缓存（Redis）与消息队列（Kafka / RabbitMQ）
- 分布式基础（CAP、BASE、限流、幂等）
- 容器基础（Docker）

### 验收标准

- 能独立负责一个中型模块
- 能定位线上 P1 故障
- 能做技术评审，给出合理方案

## 高级（3-5 年）

### 必备

- 微服务架构（Spring Cloud / Dubbo / Service Mesh）
- 分布式事务（Seata / Saga / TCC）
- 可观测性（Prometheus / Grafana / ELK）
- K8s 与 CI/CD
- 系统设计能力

### 验收标准

- 能做 100 万级 QPS 系统设计
- 能带 3-5 人小组
- 在一个方向有深度（数据库 / 性能 / 架构）

## 资深（5-8 年）

### 必备

- 多技术栈熟悉（前后端、运维、数据）
- 复杂问题拆解（架构演进、技术债务）
- 团队管理（招聘、培养、绩效）
- 跨团队协作
- 商业理解（能听懂产品话）

### 验收标准

- 能主导跨团队项目
- 能给 CTO 提技术战略建议
- 在某个垂直领域有行业影响力

## 技术专家（8+ 年）

可选方向：

- **架构师**：技术决策、跨团队架构治理
- **TL/经理**：团队管理、人才培养
- **技术专家**：深耕某一领域（数据库 / 大数据 / AI）
- **CTO**：技术战略 + 业务理解

## 学习的优先级原则

1. **先深度后广度**：3-5 年前不要追求"全栈"
2. **先原理后工具**：了解 Spring 怎么实现自动装配，再用 Spring Cloud
3. **先生产后优化**：把功能跑上线，再谈性能调优
4. **先稳定后高效**：先把故障率降下来，再谈交付速度

## 总结

技术成长不是线性的，**前 3 年是陡坡，3-7 年是平台期，7+ 年重新陡坡**。理解了这个节奏，就不会被同龄人焦虑吓到。
